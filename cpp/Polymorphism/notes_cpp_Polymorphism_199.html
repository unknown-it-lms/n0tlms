Polymorphism
​​​​​​​Object oriented programming supports two types of polymorphism:
​​​​​​​
  • Compile-time polymorphism (also called as false polymorpshim / static polymorpshim)
  • Run-time polymorphism (also called as true polymorpshim / dynamic polymorpshim)
Compile-time polymorphism
Function overloading and operator overloading are the examples of compile-time polymorpshim. They allow the programmer to write more than one functions with same name but with different signature. The compiler calls appropriate function based on the parameters passed while calling these functions.
Run-time polymorphism
This is the real polymorphism. We need to understand the concepts of generic pointer and virtual functions in C++, to understand run-time polymorphism.

Lets now study following important concepts related to real polymorphism:
  1. Generic pointers
  2. Typecasting
  3. Static and dynamic binding
  4. Virtual functions
  5. ​​​​​​​Function overriding
  6. Implementing polymorpshim
Generic pointers
In C++, pointer of base class can point to objects of its derived classes. Such type of pointer is called as generic pointer. This is possible because the objects of derived class inherit ALL state and ALL behavior from the base class. Hence, everything that one expects from base class can always be fulfilled by objects of derived class.

Note that
  • Only base class pointer can point to objects of its own types and other types derived from it.
  • Derived class pointer can't point to objects of base class. It can't point to objects of peer level classes also.
Employee* pE1, pE2, pE3, pE4;

Typecasting
We have seen that generic pointer can point to objects of derived classes BUT there is a limitation to this. Using a generic pointer, though we can point to the object of derived class, we can't access the additional class members added by that derived class. We can only access those members which are already present in the class of generic pointer.
If we want to access the additional members of the derived class, we have to type-cast the generic pointer to the derived class type. After such type-casting, we can access the additional members of the derived class also. 
Down-casting
Such type of type-casting which changes a pointer from base class pointer to derived class pointer is called as down-casting.
Up-casting
The type of type-casting which changes a pointer from derived class pointer to base class pointer is called as up-casting.

Lets understand this through the following example:

Static and dynamic binding
Whenever a function is called in a program, the process of searching the exact function to be called, is called as function binding. 

There are two ways in which functions binding is done:
  1. Static binding
  2. Dynamic binding

Static bindingDynamic binding
In static binding, the decision of actual function to be called is taken by the compiler during compilation, hence it is called as compile-time binding or static binding. In dynamic binding, the decision of actual function to be called is taken at run-time (during actual program execution), hence it is called as run-time binding or dynamic binding.

The function is called on the basis of type of object or type of pointer used for calling the function. The function is called on the basis of type of object pointed by the pointer (not on the basis of type of pointer) used for calling the function.

Static binding is done for: 

  1. Global functions called from our program
  2. Member functions called using object
  3. Static functions called using class name
  4. Non-virtual functions called using generic pointers
Dynamic binding is done ONLY for:

  1. Virtual member functions called using generic pointer (or generic reference)
Examples of static binding:

class Employee: public Person
{
    public:
    void Display();
};

void main()
{
    Add(12,13); // Global function call

    Employee e1;
    e1.Display(); /* Member function called using object */

    Employee::getCount(); // Static function

    Programmer p1;
    Employee* pE;
    pE=&p1;
    pE->Display(); // If Display is NOT virtual
}
 /* In all cases given above, compiler decides about the function to be called. Hence, it is static binding */		Examples of dynamic binding:

class Employee: public Person
{
    public:
​​​​​​​    virtual void Display();
};

void main()
{
    Programmer p1;
    p1.Display(); /* This is static binding, because, thought the function Display is virtual, it is called by object (not by a generic pointer) */

    Employee* pE;
    pE=&p1;

    pE->Display(); /* This is dynamic binding, If Display is virtual function and called using generic pointer. */
}

/* Here, in the function call, pointer pE is of class Employee BUT it is pointing at this moment, to object of class Programmer.

The function Display() is declared as virtual in call Employee. So we are calling a virtual function using a generic pointer. Hence, all the conditions for dynamica binding are fulfilled.

Hence, this decision is NOT taken by compiler. It it taken at the time based in type of object pointed by the pointer, which is Programmer at this moment.

Hence, Display() from class Programmer gets called.*/
Virtual functions
  • In C++, we can mark non-static member functions of a class as virtual. Such functions are called as virtual functions. Note that only non-static member functions can be virtual. Global functions and static member functions can NOT be made virtual.
  • If a virtual function is called using a pointer, the function call is not decided by the compiler. It is decided at run-time based on the data type of object pointed by the pointer, instead of the type of pointer itself. This is called as dynamic binding.

So dynamic binding takes place when following two conditions are satisfied.
  1. It must be called (invoked) using a pointer.
  2. The function must be marked as virtual in the class of pointer used for calling the function.

virtual int Add(int a,int b) // ERROR. Global functions can not be virtual
{
    return a+b;
}

Function overriding
  • Redefining a base class virtual function in its derived class is called as function overriding.
  • The derived class definition of that function has same name, same signature and same return type as that of the base class function.
  • Only definition of the function is different in the derived class.

Lets understand this with an example:

Difference between function overloading and function overriding
Function overloadingFunction overriding
Writing multiple functions with same name but with different signature is called as function overloading.Redefining a base class virtual function in derived class is function overriding.
All overloaded function has same name but signature must be different.All overridden functions has same name, same signature and same return type.
This creates static PolymorphismThis creates dynamic Polymorphism.
All types of function (global, static, non-static) can be overloaded.Only virtual functions can be override. Note that only non-static member functions can be virtual.

Implementing polymorphism
Polymorphism is different implementation of same request by different objects which are related to each other through IS-A type of relation. This is possible in C++ due to the concepts of generic pointer and dynamic binding.

Lets understand this through actual code for following two scenarios.

  • SalesManager, Admin and Programmer are the classes derived from class Employee.
