Exception Handling
Exception handling is a mechanism used in programming, to handle failures and errors that occur during run-time.
We will see following points in this topic:
  1. Need of exception handling
  2. try throw catch
  3. re-throwing exceptions
  4. Generic catch block
  5. User-defined exceptions 
Need of exception handling
A programmer is mainly responsible for following two aspects in a software.
  • Syntax of the language 
  • Logic of the program. 

However, success or failure of a software depends on many other factors which are beyond the control of the programmer. For example:
  • Memory available on the system 
  • Availability of a File needed by the program.
  • Connectivity of Database server our program is trying to connect
  • Availability of internet connectivity needed by our system
  • Correct value and format of the data accepted from the user by our program
  • Many other related to external resources etc

Errors related to above mentioned scenarios occur only when the program is running in a given context. Hence they are called as run-time error or exceptions. Such errors put our program in such a state that further execution becomes invalid. For example, if the file we are tying to open is not available, there is not point in proceeding further. An alternate path of execution should be provided for our system to come out of this state. Exception handling mechanism handle such run-time error situations without disturbing the code written for normal execution.

Lets see some common scenarios that may fail at the time of execution.
Person* p1= new Person();We are trying to create a new object of class Person here. This may fail if there is not enough memory available for the program at the time of execution of this statement. 
/* Value of a and b is accepted from the user */
double c= a/b;		Here, we are dividing number a by number b whose values are accepted from the user. If user enters 0 for b, then this leads to division by zero which is an error during the time of such execution. 
/* Value for str is accepted from the user */
char str[10];
cin >> str ;
int a = stoi(str);
cout << a;		If the user enter a wrong value (like "DAC" ) for str, which can't be parsed as an integer, this statement will give an error at run-time.
ifstream myfile;
myfile.open("d:\folder1\file.txt");		We are trying to open a file from a given location. If this file is not present at the given location with given name, this statement will give error at the time of execution.

Why throwing exceptions is better than returning a value that indicates error.
  1. A function may return some value that indicates result of exception of that function. In such case, we cant return the error value due to following reasons:
    a) A function can't return more than one values.
    b) Even if we decide to return the error value, in some situations, we may not be able to differentiate     between the success value and error value.
  2. There are some functions in OOP, like constructors, which don't return anything. We can't use the return statement in such functions.

Hence, exceptions are better mechanism for handling such error scenarios.

try throw catch
The exception mechanism in C++ as following three keywords.
  • try
  • throw 
  • catch

Syntaxtrythrowcatch
try 
{
    //code 1
    throw exception;
    //code 2
}
catch(exception e)
{
    // error handling code
}
catch(int a)
{
    // error handling code
}
  • try indicates the block of code that may throw an exception. 

  • The exception may be thrown explicitly using throw statement or it may be thrown from a function we have called from the try block.
  • throw is a keyword used for throwing an exception.

  • Once an exception is thrown in a program, further code in the try block is skipped and it starts searching for the matching catch block.
  • catch indicates the code that gets executed when an exception is thrown.

  • In the catch block, we generally write a code that takes necessary corrective action for handling the error or at least inform the user about the possible causes of exception.

  • There can be more than one catch blocks. When exception is throw, the that catch block is selected whose parameter matches with the data type of the exception throw. This search is done from top to bottom. Once a matching catch block is found, all other catch blocks are ignored.
Note that:
  • try and catch blocks always exist together.
  • There can't be try block without catch block. Similarly, there can't be a catch block without throw block.
Flow of program execution in exception scenarios:
  • Once exception is thrown, all further lines of code in the program are ignored.
  • The program starts searching for the matching catch block. The matching catch block is based on the data type of exception and data type of the parameter of the catch block.
  • Once a matching catch block is found, code inside that catch block gets executed.
  • Once the program reached to the end of matching catch block, all further catch blocks are ignored.
  • Now the execution starts from the first line after the last catch block.
  • If suitable catch block is not found, the exception is not handled at all. It is them handled by the operating system and then the program terminates. Such exception is called as un-handled exception.

re-throwing exceptions
  • In many cases, the catch block handles the exception by taking the remedial action completely.
  • However, there may be situations where it may not be possible for the catch block to take the corrective action completely. It may take part of the corrective action and wants that exception should continue further so that remaining part of corrective action can be taken in the catch block of the caller function.
  • This is made possible by writing throw inside the catch block. This way the current exception gets thrown to the calling function.
  • This is also called as partial handling of exception. 

In such case, we can "re-throw" the exception as shown below.
void f2()
{
    try
    {
        throw runtime_error("Exception from f2()");
    }
    catch (exception ex)
    {
        cout << ex.what()<< " Handled in f2()" << endl;
        throw; /* This is re-throw. If we don't mention the exception explicitly, the current exception is thrown. So at this line "throw" is equivalent to "throw ex". 
*/
    }
}
void f1()
{
    try
    {
        f2();
    }
    catch (exception ex)
    {
        cout << ex.what() << " Handled in f1()" << endl;
    }
}		int main()
{
    f1();
    return 0;
}
-----------------------------------
In this case, note that:
  • main calls a function f1() which internally calls another function f2()

  • f2() throws an exception. It handles that exception in its catch block BUT it further re-thows the same exception using statement throw. So exception is handled only partially in f2().

  • This re-thrown exception is again handled by the catch block of f1().

  • So the exception thrown in f2() is partially handled by f2 catch block and partially by catch block of f1()

Note that: 
Only catch blocks can write "throw;" without mentioning the exception. In other parts of code, we MUST mention the exception explicitly.
Generic catch block
  • In a try catch block, we generally write multiple catch blocks based on different types of exceptions thrown from the try block. Each of these catch block handles only the exceptions of the type that matches with the parameter of the catch block.
  • We can also write a catch block that can handle ALL types of exceptions irrespective of the data type of exception. Such catch block is called as a generic catch block.
  • If a try block has a generic catch block, none of the exceptions goes un-handled. So it can be good way to prevent un-handled exceptions from your code.
  • Such catch block is written as catch(...) (3 dots without space ... this is called as ellipsis)

We can understand this from the previous example, we have used.
try
    {
        int age;
        cin >> age;
        if (age < 0) throw age; // Exception of type "int" thrown here

        if (age == 0) throw 'Z'; // Exception of type "char" thrown here

        if (age > 0 && age <= 10) throw "age between 1 and 10"; // Exception of type "const char*" thrown here

        if (age > 10 && age <= 20) throw runtime_error("Age is between 11 to 20"); /*Exception of type "exception" thrown here */

        if (age > 20 && age <= 30) throw 30.24; // Exception of type "double" thrown here

        cout << "No exception is thrown." << endl;
    }
    catch (int a) // Handles only in type of exceptions
    {
        cout << "catch(int) called with "<<a << endl;
    }
    catch (exception ex) // Handles exceptions of type "exception" 
    {
        cout <<"catch(runtime_error) called with "<< ex.what() << endl;
    }
    catch (...) // All other non-matching exceptions are handled by this generic catch block
    {
        cout << "catch(...) called" << endl;
    }
Note that:
  • The search for matching catch block is done from top to bottom. This search ends when a suitable catch block is found.
  • Hence generic catch block MUST be written at the end of all other catch blocks.
  • All other catch blocks written below generic catch block will never get executed. Hence, the compiler gives an error "Handler is masked by default handler", as shown below:
try
    {
        int age;
        cin >> age;

        cout << "No exception is thrown." << endl;
    }
    
    catch (int a)
    {
        cout << "catch(int) called with "<<a << endl;
    }
    catch (char ch)
    {
        cout << "catch(char) called with "<<ch << endl;
    }
    catch (...)
    {
        cout << "catch(...) called" << endl;
    }
    catch (const char* p) // ERROR: This catch block will never get executed. So we get compile time error

        cout << "catch(const char*) called with "<<p << endl;
    }
User-defined exceptions
  • Till now we have thrown exceptions of built-in data types (like int, float, char, char* double etc). We have also seen exceptions of some built-in class types (like runtime_exception, exception etc).
  • We can also throw exceptions of the user-defined data types as well. For example, we can create a class A and throw object of class A as an exception. We can even create an hierarchy of classes and throw objects of any of these classes as exception, as demonstrated below:
class A
{
    public:
    void Display();
};
class B: public A
{
    void Display();
};
class C : public B
{
    void Display();
};

int main()
{
    try
    {
        // some code here ...
        throw A(); /* Here object of class A is created and thrown as exception. This will be handled by the catch block with A as parameter */

        // some code here ...
        throw B(); /* Here object of class B is created and thrown as exception. This will be handled by the catch block with B as parameter */

        // some code here ...
        throw C(); /* Here object of class C is created and thrown as exception. This will be handled by the catch block with C as parameter */
    }
    catch (C ex)  // Most derived class first
    {
        cout << "exception handled in catch(C ex)"<< ex.Display() << endl;
    }
    catch (B ex) 
    {
        cout << "exception handled in catch(B ex)"<< ex.Display() << endl;
    }
    catch (A ex) // Most base class last
    {
        cout << "exception handled in catch(A ex)"<< ex.Display() << endl;
    }
    return 0;
}
Note that: Here, we must write the catch blocks in the reverse order of inheritance. (first C, followed by B, followed by A). If we write the catch for A first, it will handle exceptions of type A as well as B and C also.

In the above example, we have created objects of user-defined class locally (throw A()) and then thrown. In such case, its copy gets created in the matching catch block. To avoid this, we can even create these objects dynamically and throw their pointers as shown below:

class A
{
    public:
    void Display();
};
class B: public A
{
    void Display();
};
class C : public B
{
    void Display();
};

int main()
{
    try
    {
        // some code here ...
        throw new A(); /* Here object of class A is created dynamically and thrown as exception. This will be handled by the catch block with A* as parameter */

        // some code here ...
        throw new B(); /* Here object of class B is created dynamically and thrown as exception. This will be handled by the catch block with B* as parameter */

        // some code here ...
        throw new C(); /* Here object of class C is created dynamically and thrown as exception. This will be handled by the catch block with C* as parameter */
    }
    catch (C* pEx)  // Most derived class first
    {
        cout << "exception handled in catch(C ex)"<< pEx->Display() << endl;
    }
    catch (B* pEx) 
    {
        cout << "exception handled in catch(B ex)"<< pEx->Display() << endl;
    }
    catch (A* pEx) // Most base class last
    {
        cout << "exception handled in catch(A ex)"<< pEx->Display() << endl;
    }
    return 0;
}
Note that: Here, we must write the catch blocks in the reverse order of inheritance. (first C*, followed by B*, followed by A(). If we write the catch for A* first, it will handle exceptions of type A* as well as B* and C*also. This is because, a generic pointer to point to objects of derived class as well.
