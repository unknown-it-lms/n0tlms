Notes: cpp- Reusing Classes

Reusing Classes
  • In procedural languages like C, we reused existing code with the help of functions. The code written in a function get re-used when it is called with different parameters from other parts of the code. 
  • In object oriented languages, this reuse is possible even at the level of entities, which means that, we can create an entity in our code and reuse it for creating other entities in our program.
  • This reuse of entities in C++, can be done mainly in following two ways:

  1. Containment
  2. Association

Lets see each of them in this topic.
Containment
  • Till now, we have created classes whose data members were simple built-in types like int, float, char etc.
  • In containment, we create object of one class as data member of other class.
  • The object that is being reused is called as component and the object that reuses the component is called as the container.
  • Containment creates HAS-A relationship between the container and the component objects. Here, the component objects are physically present inside the container objects Hence containment is considered to be a tight-coupling between the container and components. 

Lets understand this with some real life examples, as follows:
Car HAS engineObject of Engine class is created as data member of Car class. Here engine is called as the component and car is called as the container. One car has only one engine so this is One to one relationship 
Line HAS two pointsTwo objects of Point class are created as data members of Line class for modeling first point and second point of a line. Here point is called as the component and line is called as the container. One line has two points. So this is one-to-many relationship
Triangle HAS three pointsThree objects of Point class are created as data members of Triangle class for modeling first point, second point and third point of a triangle. Here point is called as the component and line is called as the container. One triangle has three points. So this is one-to-many relationship
Moblie HAS SIM cardOne or two objects of SIM card are created as data members of Mobile object. Here SIM card is the component and mobile is the container objectOne mobile can have more than one SIM cards. So its a one-to-many relationship.
Steps to implement containment in C++.
  1. Create object of component class as data member of container class.
  2. In the constructor of container, initialize the components using member initialization list (MIL)
  3. Reuse functionality of component by invoking appropriate methods on it.

For example, Every person has date of birth. This relation can be modeled in our code by creating object of date class as data member of person class, as follows:
person.hperson.cpp
#include"date.h"
class Person // This is container 
{
    char name[30];
    Date dob; // This is component 
public:
    Person();
    Person(const char*, Date);
    Person(const char*, int,int,int);
    void Display();
};		#include "Person.h"
Person::Person():dob(0,0,0) // MIL
{
    strcpy_s(name, "");
}

Person::Person(const char* p,Date d1):dob(d1) // MIL
{
    strcpy_s(name, p);
}
Person::Person(const char* n, int a, int b, int c):dob(a,b,c) // MIL
{
    strcpy_s(name, n);
}
void Person::Display()
{
    cout << name << " ";
    dob.Display(); // Delegation of responsibility to component 
}
main.cpp
#include"Person.h"
int main()
{
    Person p1;
    Person p2("Sachin",23,4,2008);
    
    Date dob (12,5,2005);
    Person p3("Anil", dob);

    p1.Display();
    p2.Display();
    p3.Display();
}		Note that:
  • p1 is created using default values.
  • p2 is created using parameterized constructor where the component is created by the container. In such case, the components are created first and then the container is created. Hence constructors of component get executed first and then that of container gets executed. During destruction, the container is destructed first and then the components are destroyed. Always note that the order of destructor execution is always opposite to the order of constructor execution.
  • In p3, the programmer creates the component first and it is passed as parameter to the constructor of container. (This approach is recommended as a better software design)
  • Person class delegates part of its responsibility to data class by reusing its display method. This is called as function delegation.
Association
  • Like containment, Association also reuses objects of existing classes for creating new classes. However, there is a basic difference in the way components are reused by the container.
  • In containment, components are physically present inside the container whereas in association components are logically connected to the container. The container and components have different physically existence but the container points to the component using a pointer. 
  • Containment is a rigid relationship whereas association is more flexible in nature.   
  • This relationship models many real life scenarios better than containment. For example, every person has a date of birth BUT the date of birth object is not physically present inside the person. Hence, its more appropriate to model this relationship using association, instead of containment.  
Steps to implement association in C++.
  • Create pointer of component class as data member of container class.
  • In the constructor of container, initialize the component pointer by creating the component object dynamically using new operator.
  • Reuse functionality of component by invoking appropriate methods on it using its pointer.
  • The container class has a pointer as its data member, which is initialized in the constructors. Hence we must write a destructor to de-allocate the memory allocated to the component pointer.

person.hperson.cpp
#include"date.h"
class Person // This is container 
{
    char name[30];
    Date* pDob; // This is component pointer
public:
    Person();
    Person(const char*, int,int,int);
    ~Person();
    void Display();
};		#include "Person.h"
Person::Person()
{
    strcpy_s(name, "");
    pDob= new Date(); // Component created at run-time
}

Person::Person(const char* n, int a, int b, int c)
{
    strcpy_s(name, n);
    pDob= new Date(a,b,c); // Component created at run-time
}
void Person::Display()
{
    cout << name << " ";
    pDob->Display(); /* Delegation of responsibility to component using its pointer */
}
Person::~Person()
{
    delete pDob; // delete the component object. IMPORTANT
}
main.cpp
#include"Person.h"
int main()
{
    Person p1;
    Person p2("Sachin",23,4,2008);
    
    p1.Display();
    p2.Display();
    p3.Display();
}		Note that:
  • p1 is created using default values.
  • Here the creation and deletion of the component object to totally controlled by the container object. It gets created whenever, the container creates it using new operator and gets deleted when the container deletes it using the delete operator.
Comparison
​​​​​​​Following is the comparison between containment and association relationship.
ContainmentAssociation
This creates HAS-A relationsThis also creates HAS-A relationship
Component is physically present inside containerComponent is NOT physically present inside container. It is present elsewhere but its address is stored in the container. So the components are logically associated with the container.
This is tight-coupling between container and componentThis is loose-coupling between container and component
This is generally not recommended because it makes the software quite rigid. This is recommended as the software design is flexible in nature.
