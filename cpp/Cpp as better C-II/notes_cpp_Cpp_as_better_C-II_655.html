Function Overloading
Function overloading is a feature of object-oriented programming where two or more functions can have the same name but signature. Signature of a function is decided by:
  1. Data type of parameters
  2. Number of parameters
  3. Sequence of parameters

Note that return type is NOT part of function signature.

Overloaded functions should differ from each other at least on any one of the above criterion.
Following are some of the cases of overloaded functions
int Process(int a,int b);
int Process(int a,int b,int c);
int Process(int a,int b,int c, int d);		This is allowed because though name of each function is same, each function has different signature due to different number of parameters. 
int Process(int a,int b);
int Process(float a,float b);		This is allowed because though name of each function is same, each function has different signature due to different data type of parameters.
int Process(int a,float b);
int Process(float a,float b);		This is allowed because though name of each function is same, each function has different signature due to different sequence of parameters.
int Process(int a,float b);
int Process(int a, int b,float c);
int Process(char a,float b);
int Process(int a,float b);		This is NOT allowed because function 1 and function 4 have exact name as well as signature. This is because both have same number of parameters, same data type of parameters as well as same sequence of parameters.
int Process(int a,float b);
float Process(int a,float b);		This is NOT allowed because both functions differ from each other only by the return type.
The compiler selects the function to be called by matching the parameters. Function having best match with the parameters is selected.

Name mangling (Function name decoration)

During compilation, name of each function gets changed. The new name given to each function is some combination of original function name and the function signature.

For example:
float Add(int a,int b)                  -> changed to Add_i_i
float Add(int a,int b, int c)        -> changed to Add_i_i_i
float Add(int a,float b)              -> changed to Add_i_f
and so on.

This is called as name mangling or function name decoration. The actual naming pattern varies from compiler to compiler.

const
const keyword is used in C++ in different contexts. Lets see each of them now:
const variable:
We can declare a variable as const. In that case, the variable MUST be initialized at the time of declaration itself. Once initialized at the time of declaration, it can't be reassigned any value directly of indirectly.
Code    
int main()
{
    const int a;         // Error. const variable must be initialized at the time of declaration
    const int b=10;  // Ok
    b= 12;                 // Error. const variable can't be reassigned a value
    b= 10;                 // Error. Even the same value can't be re-assigned.
    b++;                    // Error. Const variable cant be assigned value even indirectly in any way
    int c;
    c=b;                     // Ok
    cout<<a<<endl; // Ok
}
const member function:
Member function of a class can be declared as const. In that case, we can't modify state of the invoking object in any way.
Code
class Point
{
        int x,y;
    public:
        Point();
        Point(int a,int b);
        void Display() const;
};
void Point::Display() const
{
    x=20;    // Error. Can't change state of invoking object in const function
    cout<<"["<<x<<","<<y<<"]";
}		int main()
{
    Point p1(12,13);
    p1.Display();
}
const object:
We can declare an object as const. Note that const object can ONLY call const member functions. Non- const member functions can't be invoked on const object.
Code
class Point
{
    int x,y;
    public:
    Point();
    Point(int a,int b);
    void SetX(int a); // This is non-const member function
    void Display() const; // This is const member function

void Point::Display() const
{
    cout<<"["<<x<<","<<y<<"]";
}
void Point::SetX(int a)
{
    x=a;
}		int main()
{
    const Point p1(12,13);
    p1.SetX(23); // Error
    p1.Display(); // Ok
}

inline functions
  • When a function is called, there is lot of overhead involved in the call to that function. For example, a stack frame is allocated for the function, parameters and local variables are created on the stack frame. Then the function gets executed and once it returns all local variables are removed from the stack frame and finally the stack frame itself is removed from the memory. Such overheads are justified for large size functions but not for very small functions which may be of only couple of lines of code. 
  • To avoid this function call overhead, such functions can be declared inline. Inline functions are expanded inline hence don't need the function call overheads discussed above.
  • Note that inline is just a request to the compiler to consider the function for inlining. Compiler will actually decide whether to inline the function or not, based on function size and other factors.
  • Functions that are defined inside the class are automatically considered for inlining.
  • Declaring functions as inline can be quite beneficial for real-time applications like embedded systems when performance of the software is very crucial.
Creating inline member functions
class Date 
{
    int d,m,y;
public:
    inline int getDay();
    int getMonth()
    {    
        return m;
    }
}		/* inline keyword is used only in declaration, not in definition */
int Date::getDay()
{
    return d;
}

Note that:
  • Here getDay is declared as inline in class explicitly because it is defined outside the class. BUT
  • getMonth is automatically considered for inlining because it is directly defined in the class.

 Benefits of inline functions over macros:
We can use macros which serve the almost same purpose of inline functions. However, it is strongly recommended to use inline functions instead of macros, due to following reasons:
  • Macros are handled by the pre-processor. It simply replaces the macro name with the macro code without doing type-checking. On the other hand, inline functions are handled by the compiler, which performs necessary type checking in the inline function. Hence, it is guaranteed to be type-safe. 
  • Marcos can't access private members of the object. Whereas, we can access private members inside an inline function, if it is declared as a member function of that class.
