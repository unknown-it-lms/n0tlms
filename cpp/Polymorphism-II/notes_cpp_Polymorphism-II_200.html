Polymorphism-II
In the previous topic, we have seen basic concepts related to Polymorphism. In this topic, we will see following advanced features related to Polymorphism.

  1. Pure virtual functions
  2. Abstract class
  3. Virtual destructor
  4. V-Table and V-pointer 
Pure virtual functions
  • ​​​​​​​In Polymorphism, we have seen that the function we expect to behave polymorphically, must be declared as virtual in the base class, and then overridden in derived classes. However, in the base class when we declare the function as virtual (which is compulsory), we MUST define that function, else the linker gives error as it couldn't find definition for that function. 
  • However, In many cases, it is logically not possible to define such functions in base class. In such cases, we want freedom to just declare the function as virtual in base class but not define in the base class. 
  • In such cases, we can declare the virtual function as pure virtual function.
  • Once the function is made pure virtual in base class, it NEED not be defined in the base class.
  • Note that only virtual functions can be made pure virtual.

To declare a virtual function as pure virtual function, we just write =0 after its declaration, as shown below:
​​​​​​​
virtual void Display(); // This is virtual function. It must be defined
virtual void Display()=0; // This is pure virtual function. It NEED not be defined.

Abstract class
  • ​​​​​​​If a class contains, pure virtual function, it can't be considered as a complete class. Hence, we can not create its object. Such class is called as abstract class.
  • Though we can't create objects of abstract class, we can create its pointer as well as references. Such pointer of abstract class can point to objects of derived classes. 
  • If the class derived from the abstract class overrides the pure virtual function by defining it, it no longer remains incomplete. Such class is called as concrete class. Objects of concrete class can be created.
  • But, if the pure virtual function is not overridden in the derived class, even the derived class becomes abstract and its instance can not be created. ​​​​​​​

/*class Employee becomes abstract now, because it has a pure virtual function.*/
class Employee : public Person
{
protected:
    int id;
    double basicSal;
public:
    Employee();
    Employee(char*,int,int,int,int,double);
    virtual void Display()=0; /* Display is here made a pure virtual function. There is no need to define this function now. */
};
--------------------------------------------------------

class Admin: public Employee 
{
    public:
    void Display()
    {
        /* Pure virtual function of base class is defined here. So class Admin is concrete class. */
    }
};
--------------------------------------------------------

class SalesManager: public Employee 
{
    public:
     /* Inherited pure virtual function is not overridden, so even class SalesManager is abstract now */
};

int main()
{
    Employee* pEmp; /* OK. Pointer of abstract class can be created */

    Employee e1; /* ERROR. Object of abstract class can NOT be created. */

    Admin a; /*Admin class overrides the pure virtual method. So it is a concreate class. Its objects can be created. */

    Employee& refEmp = a; /*OK. Even references of abstract class can be created to refer to objects of derived class*/

    SalesManager s1; /* ERROR. Object of abstract class can NOT be created. */
}
Virtual destructor
Earlier, we have seen that when the object of derived class gets created, constructors are called in the order of base class to derived class. When it gets destroyed, destructors are called in the reverse order i.e. from derived class to base class.
The reverse order of destructor execution ensures that all destructor in the hierarchy get called and hence all resources are release properly. 

However, this is not the case, when we delete a dynamically created derived class object using base class pointer, as shown in the following scenario:
class A
{
public:
    A() { cout << "Constructor of A called" << endl; }
    ~A() { cout << "Destructor of A called" << endl; }
};

class B: public A
{
public:
    B() { cout << "Constructor of B called"<<endl; }
    ~B() { cout << "Destructor of B called" << endl; }
};

class C : public B
{
public:
    C() { cout << "Constructor of C called" << endl; }
    ~C() { cout << "Destructor of C called" << endl; }
};		void main()
{
    A* pA= new C();
    //... 
    // Now lets delete this object
    delete pA; /*Here the destructor is indirectly called using pointer of class A. As the destructor is not virtual, this becomes static binding. Hence only destructor of class A gets called. This can lead to resource leakage.*/
}
​​​​​​​
To avoid this, we have to declare the destructor virtual in the base class, as shown below
class A
{
public:
    virtual A() { cout << "Constructor of A called" << endl; }
    ~A() { cout << "Destructor of A called" << endl; }
};		void main()
{
    A* pA= new C();
    // ...
    // Now lets delete this object

    delete pA; /*Here the destructor is indirectly called using pointer of class A. As the destructor is virtual, this becomes dynamic binding. Hence destructor of class C gets called, which internally calls destructor of class B, which internally calls destructor of class A. As all destructors get called, there is NO resource leakage.*/
}

V-table V-pointer
  • ​​​​​​​V-table stands for Virtual table.
  • V-pointer stands for Virtual pointer.

This is the mechanism created by the compiler to achieve run-time Polymorphism. This setup of V-table and V-pointer is created only for classes having at least one virtual functions inside them. For other classes, this mechanism is not created.
V-table:
This is an array of pointers to all virtual functions of the class. It is stored as static data member of the class. It is created only if the class has at least one virtual function added either directly or inherited from the base class. 
V-pointer:
V-pointer points to the V-table. It is non-static data member stored in every object created from the class having V-table. 

Note that:
  • Dynamic binding at tun-time is achieved by searching its function pointer (which is present in V-Table) using the V-pointer (which is present in the object).
  • The memory allocated to the V pointer and V table is the cost we pay for getting Polymorphism in our program.
