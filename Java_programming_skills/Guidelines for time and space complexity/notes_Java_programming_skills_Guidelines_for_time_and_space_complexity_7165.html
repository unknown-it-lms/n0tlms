Guidelines for time and space complexity
NoGuideline
1Use Defensive coding. All parameters should be validated right at the beginning. The most frequent possible case first and so on. Return immediately if data is not valid.
2No variable declarations inside loop. Declare them outside and initialize.
3No function calls inside the loop unless logically needed. Call the function once, store it value outside the loop.
4Use StringBuilder if strings are getting composed frequently. This saves lot of execution time.
5Use most suitable data types. Don’t unnecessarily use larger data types.
6Use indentation.
7Give appropriate comments but avoid un-necessary comments too.
8Try to do Dynamic programming. Cache the results in a hashtable and see if they can be used further.
9Use HashSets as much as possible, when you want fast search of data.
10Try to avoid nested loops as much as possible. They cost a lot in larger values.
11Use meaningful but short names. Avoid a,b,c,x,y,z etc
12Use primitive types (int, long, double, etc.) instead of their wrapper classes (Integer, Long, Double, etc.) whenever possible, as wrapper classes involve object creation and autoboxing/unboxing overhead.
13For iterating over collections, the enhanced for-loop is often more readable and can sometimes be optimized better by the compiler. However, if you need the index or need to modify the collection during iteration, a traditional for-loop with an Iterator might be necessary.
14Avoid Unnecessary Operations in Loops: Move computations that don't change within a loop outside of it.
15Early Exit: Use break or return to exit loops as soon as the desired condition is met.
16final variables ensure that their values are set once, which can help with readability and sometimes enable minor optimizations.
17Short-Circuiting: Use && and || for short-circuiting logical operations to avoid evaluating unnecessary conditions.
18Avoid System.out.println
19Identify Bottlenecks: Focus your optimization efforts on the areas of your code that consume the most resources. Optimizing non-bottleneck code will have little to no impact.
20Understand the Basics of JVM and Memory Management.  Understand that local variables and method calls are on the stack (fast access), while objects are on the heap (slower access, garbage collected).
21Choose the Right Data Structures and Algorithms:
22Minimize object creation
23Use primitive types when possible
24Avoid using == for object comparison (use .equals()).
25Cache results of expensive computations
