Express Middleware
This is very important feature provided by Express.js which is not avaialble in Node.JS. It allows to perform some repeatative task to be executed by writing only one function which is common to multiple request handlers. 
What is middleware
Express JS middlewares are the functions that get executed in the middle of the sequence of request processing. These functions can be used for modifying the incoming request and/or modifying response. The incoming request will be automatically passed through a set of middleware functions.  Middleware functions are functions that have access to the request object (req), the response object (res), and the next function in the application’s request-response cycle. This allows to split the code into multiple blocks instead of having one huge function that does everything and modify the req and res object. This promotes even the re-usabilty where one middleware can be associated with multiple route handlers.
Scenarios where middleware is required
Logging the request information
Encryption and decryption of password
Adding the custom header in the response
Compressing the response
Reading cookies from request
Functions of middleware
It can execute any code.
It can make changes to the request and the response objects.
It can end the request-response cycle.
It can call the next middleware function in the stack.

Syntax of Middleware
app.use('route path',function(request, response, next){
})
  1. app represents express application
  2. use() method indicates it is a middleware function call
  3. 'route path' will be the first argument which indicates the request url for which middleware function gets executed. This argument is optional. If not specified, middleware gets executed for all requests
  4. function(request, response, next) is the mandatory second argument which is a function with 3 arguments
Types of Middleware functions
  • Built-in middleware provided by Express like express.static, express.json, express.urlencoded
  • Custom middlewares written for specific requirement
  • Third-party middleware maintained by the community
Order of execution of middleware functions
Middleware functions get executed exactly in the same sequence the way they are written in the express application. Every middleware function needs to give a call to next() at the end of middleware logic. Call to next() is very crucial which executes the next middleware or the route handler for the given request.
Custom Middlewares
Custom middleware is a middleware function that is created by the developer to add custom functionality to the Express.js application. Custom middleware can be used to perform a wide range of tasks such as authentication, logging, data validation, error handling, reading cookies and many more.
Middleware can be bound to an instance of the app object by using the app.use() and app.METHOD() functions, where METHOD is the HTTP method of the request that the middleware function handles (such as GET, PUT, or POST) in lowercase.
Code   Description
const express = require('express')
const app = express()
app.use((req, res, next) => {
  console.log('Time:', Date.now())
  //call to next() is important
  next();
})		This middleware function is executed every time the app receives a request.
app.use('/user/:id', (req, res, next) => {
  console.log('Request Type:', req.method);
  next();
})		This middleware function is executed every time the app receives a request with url "/user/<id>"
const express = require('express')
const app = express()
app.get("/", function(req, res, next){
    response.send("Hello World!");
    next();
});
app.use('/', function(req, res){
   console.log('End');
});
app.listen(3000, function(){ 
    console.log('Server is running at http://localhost:3000');
});		This middleware function is executed after processing the request in the route handler which displays the message "end" on the console.
Error-handling middleware
Define error-handling middleware functions in the same way as other middleware functions, except with four arguments instead of three, specifically with the signature (err, req, res, next)):
Code   Description
app.use((err, req, res, next) => {
  console.error(err.stack)
  res.status(500).send('Something broke!')
})		This middleware function acts as a error handling router with one additional err object as argument.

Built-in Middleware
Built-in middleware functions are bundled with Express so we do not need to install any additional modules for using them.
Express provides the following Built-in middleware functions:
Function Description
express.staticserves static assets
express.jsonparses JSON payloads
express.urlencoded parses URL-encoded payloads
express.raw parses payloads into a Buffer and makes them available under req.body
express.textparses payloads into a string
Using express.static for Serving Static Assets
We use the express.static built-in middleware function to serve static files such as images, CSS files, and JavaScript files. Here is an example of using express.static to serve our HTML and image files.
CodeDescription
var exp = require('express');
var app = exp();
//static resources will be searched in images folder
app.use(exp.static('images'));
app.get('/image',function(req,res){
    res.send("<img src='sample.jpg' width='200' height='200' /> ");
})
app.all('*', function(req,res) {
    res.send("<p> Pl check URL </p>");
});
app.listen(9000, function() {
    console.log("exp server at 9000");
});
  • Here a static path is defined as 'images' which is name of the folder which should be present in the current directory of express application
  • When any static resource is referred from the express application, it will be always searched in the static path defined with static middleware
const express = require('express');
const app = express();
//static resources will be searched in images folder first and then in htmls folder.
app.use(express.static('images'))  
app.use(express.static('htmls'))   
app.get('/product', (request, response)=>{
  response.sendFile("productsample.html")
})
  • There can be more than one static paths defined with different directories
  • When any static resource is referred from the express application, it will be always searched in the static paths one after another till it is found
const express = require('express');
const app = express();
app.use(express.static('images'))  
app.use(express.static('htmls'))   
app.get('/product', (request, response)=>{
  response.sendFile("productsample.html")
})
Here we have defined two static paths named images and htmls to represent two folders of the same name in our root directory. We have also defined multiple static assets directories by calling the express.static() middleware function multiple times.

Express looks for the files in the order in which we set the static directories with the express.static middleware function. In our example, we have defined the images directory before htmls. So Express will look for the file: productsample.html in the images directory first. If the file is not found in the images directory, Express looks for the file in the htmls directory.
Next we have defined a route with url product to serve the static HTML file productsample.html. The HTML file contains an image referred only with the image name sample.jpg:

express.json() built-in middleware
express.json() is a built-in middleware function in Express. This method is used to parse the incoming requests with JSON payloads and is based upon the bodyparser. This method returns the middleware that only parses JSON and only looks at the requests where the content-type header matches the type option. 
It works like following
  • express.json() middleware is placed before your route handlers.
  • When a request with a Content-Type header of application/json is received, the express.json() middleware parses the request body.
  • The parsed JavaScript object is then made available as the req.body property within your route handlers.
Syntax:
express.json( [options] )
Parameters: The options parameter have various property like inflate, limit, type, etc. 
Return Value: It returns an Object. 
Simple example:
const express = require('express');
const app = express();
const PORT = 3000;
app.use(express.json());
app.post('/users', function (req, res) {
    const userData = req.body;
    console.log(userData)
    res.end();
})
app.listen(PORT, function (err) {
    if (err) console.log(err);
    console.log("Server listening on PORT", PORT);
});
Note : When request is sent from the client for root url, request header 'content-type' should be set to 'application/json'
