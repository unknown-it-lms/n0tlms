Internet and WWW
Understanding internet
Internet is interconnected networks. It is a global network of billions of computers and other electronic devices. It can be even referred as network of networks which consists of private, public, academic, business, government networks. The connection between different computers and devices could be either wired using cables or wireles using radio waves. Internet connectivity is the lifeline that connects humans to a world of information and communication which has become very essential part of our day to day life.
History of internet
Earlier, when computers used to communicate with each other, all of the data had to be sent in one packet, and if the connection was interrupted at any time during the process, none of the data would reach. Scientists developed a different method called packet switching to overcome this problem. The data could be broken up into smaller segments, and each segment could be sent individually. Smaller the data, lesser the time, and even if there is an interruption, part of the data has already reached and there is no need to start from the beginning. These smaller packets can be reassembled at the destination.
In early 1960's U.S. military's research agency (ARPA - Advanced Research Project Agenecy) created ARPANET, a network of computers designed to withstand a military (nuclear) attack. This network used packet switching. Initially certain academic and research organizations were part of this network. 
Working of internet
​
Each computer connected to the Internet must have a unique address. Internet addresses are in the form nnn.nnn.nnn.nnn where nnn must be a number from 0 - 255. This address is known as an IP address. Data sent over the Internet (and most computer networks) are sent in manageable chunks. These chunks of data are known as packets. The packets would go through the Application Layer and continue to the TCP layer. After going through the TCP layer, the packets proceed to the IP layer where it receives it's destination address. The hardware layer takes care of turning the data in the packets into electronic signals and transmitting them over the network.
At the receiving end,  the packets start at the bottom of the destination computer's TCP/IP stack and work upwards from harware layer to IP layer, from IP layer to TCP layer, annf finally reaches the application layer.
The World Wide Web
The World Wide Web(WWW) is just one of the services running on the Internet. It can be considered as hypertext-based information system. The WWW or web is a collection of publicly accessible documents (text, images, audio, video, etc.). Users view the pages via a browser (Internet Explorer, Chrome, Firefox, Opera, etc.) running on the local machine. The webpages often contain hypertext links referring to other webpages or documents. This allows user to navigate from one web page to another.​​​​​​​
URL
​​​​​​​A Uniform Resource Locator (URL), even known as a Universal Resource Locator, is the address of a resource on the Internet. URL is often referred to as web address. A URL contains the following information:
  1. The protocol used to access the resource.
  2. The location of the server i.e. IP address or domain name.
  3. The port number on the server (optional).
  4. The location of the resource in the directory structure of the server.
​​​​​​​Given this, the following URLs are much simpler to understand:
http://www.google.com/default.htm
This URLs indicates that there is a file named default.htm on a server with the address of "google.com".
Domain Name System
DNS, or Domain Name System, is like the internet's phone book. It translates human-friendly domain names (like www.example.com) into IP addresses (like 192.0.2.1) that computers use to identify each other on the network. When browser resolves the URL, it uses cache at different levels to get the information about IP address for the domain name in the URL.​​​​​​​
Web server and HTTP
Web Server
A web server is a computer that stores and delivers web pages and web applications. It's a computer program that sends web pages as requested by the client. When a user types a website address into their browser, the browser sends a request to the web server associated with that address. The web server then retrieves the requested content and sends it back to the browser for display. The basic objective of the web server is to store, process and deliver web pages to the clients. This communication is done using Hypertext Transfer Protocol (HTTP).
The content provided by the web server can be:
static: for example, a page that gives information about history of an organization, which will be same for all users at all times)
dynamic: for example, home page of email server which shows different emails based on the user who has logged-in or a web page showing score of an ongoing cricket match.
To deliver dynamic content, most web servers support server side scripting languages like java, Javascript, PHP, .NET etc so that client's request can be processed and response can be generated dynamically.
Most widely used web server software:
  1. Apache HTTP Server
  2. Microsoft Internet Information Services (IIS)
Website
A website is a collection of static web pages such as HTML pages, images, graphics etc. Static web pages are stored in the file system of web server which displays the same information to all clients. 
Web application
A Web application is a web site with dynamic functionality on the server. Examples of web applications include blogs like Twitter, online shopping like Amazon, search engines like Google. 
Dynamic pages are constructed by a program that produce the HTML. This type of web application provides different information to different users based on their identity or few other parameters.
Working of Web
We already know that to open a web page we enter URL or click on link. The web browser then, displays web page that we request. Following are the steps that happen behind the scene.
  1. The user enters a URL in the browser.
  2. The browser sends a request to the web server over the internet.
  3. Web server examines the request and based on the request, server finds the requested page already stored in its local drive.
  4. Web Server sends the response to the web client (browser).
  5. Browser gets the HTML and renders it for the user.   
​
HTTP (Hyper Text Transfer Protocol)
  1. HTTP is a protocol that clients and servers use to communicate on the web.
  2. HTTP is application level protocol that sits on the top of TCP/IP. HTTP can not establish the connection but sends request or response on already established connections.
  3. HTTP is a stateless protocol. This means that with HTTP the clients connect to the server to send one request and then disconnects. This mechanism allows more users to connect to a given server over a period of time.
  4. The client sends an HTTP request and the server answers with an HTML page to the client, using HTTP.
  5. The server does not retain any information about previous requests from the same client.
HTTP Methods 
GET   Request to retrieve information from server using a given URI.      
POST Request for server to accept the data given in the body of HTTP request.
PUT  This is same as POST, but POST is used to create, PUT can be used to create as well as update. It replaces all current representations of the target resource with the uploaded content.
DELETE  Request for the server to delete the resource.
HEADIt is similar to get but it is used to request only the headers of a resource, not the body.
OPTIONSIt allows to client to know about various methods that can be performed on a specific resource
CONNECTIt is commonly used for creating secure, end-to-end communication channels.

HTTP request and response
HTTP (Hypertext Transfer Protocol) is the foundation of how data is exchanged on the World Wide Web. It defines the rules for how clients (like your web browser) can request information from servers and how servers can respond to those requests.
HTTP Requests
When the user clicks on a link or type a URL into the browser, the browser sends an HTTP request to the web server associated with that address. This request includes:
  1. Start Line
    It consists of information about 3 elements. 
    1. Method: The HTTP method used to request the resource (e.g., GET, POST, PUT, DELETE) that describes about the action to be performed on the server.
    2. Request-URI: The Uniform Resource Identifier (URI) of the resource being requested
    3. HTTP-Version: The version of HTTP being used (e.g., HTTP/1.1).
  2. Headers
    This part of the request is optional. It consists of case insensitive string consisting of key-value pairs separated by a colon (':'). Many differnt headers like User-Agent, Host, Connection, Content-Length can appear in requests
  3. Body
    The final part of the request is its body. All requests need not have body. Requests that send data to the
    server such as PUT or POST requests, generally require a body with the data. 
Example HTTP request
GET /index.html HTTP/1.1
Host: www.example.com

HTTP Response
An HTTP response is a message sent from a server to a client in response to an HTTP request. It consists of following parts :
  1. Status Line
    It has 3 main elements
    HTTP-Version: The version of HTTP being used (e.g., HTTP/1.1).
    Status-Code: A three-digit numeric code indicating the status of the request (e.g., 200 OK, 404 Not Found, 500 Internal Server Error).
    Status text. A brief, purely informational, textual description of the status code to help a human understand the HTTP message. e.g. "OK", "Not Found", "Internal Server Error" etc.
  2. Headers
    It follows the same structue like request headers. It is completely optional.
    Example headers:
    Server: The name of the HTTP server that generated the response.
    Date: The date and time the message was sent.
    Content-Type: The media type of the response-body.
    Content-Length: The length of the entity-body in bytes.
    Set-Cookie: Sets a cookie in the client's browser.
  3. Body
    The last part of a response is the body which may consists of contents of a web page or file. All responses may not have a body. 

Example HTTP response
HTTP/1.1 200 OK
Date: Fri, 23 Aug 2024 10:51:13 GMT
Server: Apache/2.4.54 (Win64) PHP/7.4.33
Content-Type: text/html
Content-Length: 23

<!DOCTYPE html>
