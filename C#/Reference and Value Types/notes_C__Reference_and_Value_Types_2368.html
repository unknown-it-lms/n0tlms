Notes: C#- Reference and Value Types

Reference and Value Types
​​​​​​​In C#, these data types are categorized based on how they store their value in the memory. C# includes the following categories of data types:
  1. Value type
  2. Reference type
  3. Pointer type
Reference Types
​​​​​​​Reference type doesn't store its value directly. Instead, it stores the address where the value is being stored.
In other words, a reference type contains a pointer to another memory location that holds the data.

For example, consider the following string variable:
string s = "Hello World!!";

The following image shows how the system allocates the memory for the above string variable.

​
The followings are reference type data types:
  • String
  • Arrays (even if their elements are value types)
  • Class
  • Delegate

Note:
  1. The default value of a reference type variable is null when they are not initialized. Null means not referring to any object.
  2. The reference types are stored on heap.  
  3. When assigning one reference variable to another reference variable, only the reference is copied. The actual value remains the same.
Value Types
  1. A data type is a value type if it holds a data value within its own memory space. It means the variables of these data types directly contain values.
  2. Value types are stored on the stack and are passed by copying.
  3.  This means that when a value type variable is created, the memory for it is allocated on the stack.
  4. The stack is a region of memory that is used to store temporary data, such as function arguments and local variables. Because value types are stored on the stack, they are typically accessed more quickly than reference types, which are stored on the heap.
  5. Value types in C# include simple types such as integers, floating-point numbers, and Booleans, as well as enumerations and structures. In contrast, reference types, such as objects and arrays, are stored on the heap and are accessed through references.
  6. ​​​​​​​All the value types derive from System.ValueType.

​​​​​​​Value types include the following: 
  • All numeric data types 
  • Boolean , Char ,and Date 
  • All structures, even if their members are reference types .
  • Enumerations, since their underlying  type is always SByte , Short , Integer , Long , Byte , UShort , UInteger , or ULong 
  • Every structure is a value type, even if it contains reference type members. For this reason, value types such as Char and Integer are implemented by .NET Framework structures.

​​​​​​​Passing Value Type Variables
When you pass a value-type variable from one method to another, the system creates a separate copy of a variable in another method. If value got changed in the one method, it wouldn't affect the variable in another method.

struct 
  1. Structure is a value type and a collection of variables of different data types under a single unit. 
  2. It is almost similar to a class because both are user-defined data types and both hold a bunch of different data types

Defining Structure: 
  1. In C#, structure is defined using struct keyword. 
  2. Using struct keyword one can define the structure consisting of different data types in it. 
  3. A structure can also contain constructors, constants, fields, methods, properties, indexers and events etc. 

Syntax:
Access_Modifier struct structure_name
{
    // Fields
   // Parameterized constructor
   // Constants
   // Properties
   // Indexers
   // Events
   // Methods etc.
  
}

Example:
using System;

public struct Person
    {
        // Fields
        public string Name;
        public int Age;

        // Constructor
        public Person(string name, int age)
        {
            Name = name;
            Age = age;
        }

        // Method
        public void PrintDetails()
        {
            Console.WriteLine($"Name: {Name}, Age: {Age}");
        }
    }

    class Program
    {
        static void Main()
        {
            // Creating and using a struct instance
            Person person1 = new Person("Alice", 30);
            person1.PrintDetails();

            // Modifying struct fields
            Person person2 = person1;
            person2.Name = "Bob"; // Changes the name for person2, not person1

            person1.PrintDetails(); // Still prints "Alice"
            person2.PrintDetails(); // Prints "Bob"

            Person p3;
            p3.Name = "John";
            p3.Age = 20;
            p3.PrintDetails();
        }
    }		Output:
Name: Alice, Age: 30
Name: Alice, Age: 30
Name: Bob, Age: 30
Name: John, Age: 20

Out and ref
  • Ref and out keywords in C# are used to pass arguments within a method or function.
  • Both indicate that an argument/parameter is passed by reference.
  • By default parameters are passed to a method by value.
  • By using these keywords (ref and out) we can pass a parameter by reference.

Ref Keyword
  1. The ref keyword passes arguments by reference. 
  2. It means any changes made to this argument in the method will be reflected in that variable when control returns to the calling method. 

Example:
using System;

public class Program
{
    static void Main()
    {
        int number = 5; //Need to initialised value
        Console.WriteLine("Original number: " + number);

        // Passing the variable by reference using ref keyword
        ModifyNumberRef(ref number);

        Console.WriteLine("Number after modification using ref: " + number);
    }

    // Method that modifies the number using ref keyword
    static void ModifyNumberRef(ref int num)
    {
        num = 10;
    }
}		Output:
Original number: 5
Number after modification using ref: 10
Out Keyword
  1. The out keyword passes arguments by reference.
  2. This is very similar to the ref keyword.

Example:
using System;

public class Program
{
    static void Main()
    {
        int result; //No need to initialised value
        
        // Passing a variable using out keyword
        Calculate(out result);

        Console.WriteLine("Result after calculation using out: " + result);
    }

    // Method that assigns a value to the out parameter
    static void Calculate(out int value)
    {
        // The out parameter must be assigned before the method returns
        value = 15;
    }
}		Output:
Result after calculation using out: 15

Difference between Ref and Out:
Ref
Out
The parameter or argument must be initialized first before it is passed to ref.
It is not compulsory to initialize a parameter or argument before it is passed to an out.
It is not required to assign or initialize the value of a parameter (which is passed by ref) before returning to the calling method.
A called method is required to assign or initialize a value of a parameter (which is passed to an out) before returning to the calling method.
Passing a parameter value by Ref is useful when the called method is also needed to modify the pass parameter.
Declaring a parameter to an out method is useful when multiple values need to be returned from a function or method.
It is not compulsory to initialize a parameter value before using it in a calling method.
A parameter value must be initialized within the calling method before its use.
When we use REF, data can be passed bi-directionally.
When we use OUT data is passed only in a unidirectional way (from the called method to the caller method).

Both ref and out are treated differently at run time and they are treated the same at compile time.

Properties are not variables, therefore it cannot be passed as an out or ref parameter.

nullable types
  1. In C#, the compiler does not allow you to assign a null value to a variable. So, C# 2.0 provides a special feature to assign a null value to a variable that is known as the Nullable type.
  2.  The Nullable type allows you to assign a null value to a variable. Nullable types introduced in C#2.0 can only work with Value Type, not with Reference Type. 
  3. The nullable types for Reference Type is introduced later in C# 8.0 in 2019 so that we can explicitly define if a reference type can or can not hold a null value. 
  4. The Nullable type is an instance of System.Nullable<T> struct. Here T is a type which contains non-nullable value types like integer type, floating-point type, a boolean type, etc. For example, in nullable of integer type you can store values from -2147483648 to 2147483647, or null value.  

Syntax: 
Nullable<data_type> variable_name = null;
Or
datatype? variable_name = null;
Example:  
//This will give compile time error
            int c = null;

            //Valid Declaration 
            int? a = null;

            //or Valid Declaration
            Nullable<int> b = null;
        
Characteristics of Nullable types
  1. With the help of nullable type you can assign a null value to a variable without creating nullable type based on the reference type.
  2. In Nullable types, you can also assign values to nullable type. 
  3. You can use Nullable.HasValue and Nullable.Value to check the value. If the object assigned with a value, then it will return “True” and if the object is assigned to null, then it will return “False”. If the object is not assigned with any value then it will give compile-time error.
  4. You can also use == and ! operators with nullable type.
  5. You can also use GetValueOrDefault(T) method to get the assigned value or the provided default value, if the value of nullable type is null.
  6. You can also use null-coalescing operator(??) to assign a value to the underlying type originate from the value of the nullable type.
  7. Nullable types do not support var type. If you use Nullable with var, then the compiler will give you a compile-time error.

Advantage of Nullable Types: 
  1. The main use of nullable type is in database applications. Suppose, in a table a column required null values, then you can use nullable type to enter null values.
  2. Nullable type is also useful to represent undefined value.
  3. You can also use Nullable type instead of a reference type to store a null value.

Nullable reference types
​​​​​​​Since the introduction of generics in C# 2, value types can be declared nullable or non-nullable:
int nonNullable = null; // compiler error
int? nullable = null;

In C# 8, nullable reference types use the same syntax to give the option of declaring reference types as nullable (i.e. allowing a null value) or non-nullable (not allowing a null value):

string nonNullable = null; // compiler warning
string? nullable = null;

Because of the language history, the decision to use the same syntax for value types and reference types changes the behavior of the language for reference types. Before C# 8, all reference types were nullable. They were however declared without a question mark:

// before C# 8
string nullableString;
// since C# 8
string nonNullableString;

To avoid such a breaking change in a new version of the language, the nullable reference types is the only feature of C# 8 that isn’t enabled by default. An explicit opt-in is required for each project.
The following property must be added to the project file for that:

<Nullable>enable</Nullable>

In recent versions of Visual Studio 2019, the option is also available on the Build page of the Project Properties window:

? and ?? 
  1. The null-coalescing operator ?? returns the value of its left-hand operand if it isn't null; otherwise, it evaluates the right-hand operand and returns its result. 
  2. The ?? operator doesn't evaluate its right-hand operand if the left-hand operand evaluates to non-null. 
  3. The null-coalescing assignment operator ??= assigns the value of its right-hand operand to its left-hand operand only if the left-hand operand evaluates to null. 
  4. The ??= operator doesn't evaluate its right-hand operand if the left-hand operand evaluates to non-null.

Example:  
static void Main(string[] args)
        {
            Console.WriteLine("Coalescing operator I");
            int? a = null;
            int res = a ?? 100;
            Console.WriteLine("value of a: "+a);
            Console.WriteLine("value of res: "+ res);

            res = a ??= 100;
            Console.WriteLine("value of a: "+a);
            Console.WriteLine("value of res: "+ res);

            Console.WriteLine("Coalescing operator II");
            Nullable<int> b = null;
            Console.WriteLine(b ?? 30);
            b ??= 50;
            Console.WriteLine("value of b: "+ b.Value);
            b ??= 700;
            Console.WriteLine("value of b: "+ b.Value);
}		Output:

Boxing and Unboxing
  1. Boxing and unboxing are important concepts in C#. 
  2. The C# Type System contains three data types: Value Types (int, char, etc), Reference Types (object) and Pointer Types. 
  3. Basically, Boxing converts a Value Type variable into a Reference Type variable, and Unboxing achieves the vice-versa. 
  4. Boxing and Unboxing enable a unified view of the type system in which a value of any type can be treated as an object. 

Boxing in C#
  1. The process of converting a Value Type variable (char, int etc.) to a Reference Type variable (object) is called Boxing.
  2. Boxing is an implicit conversion process in which object type (super type) is used.
  3. Value Type variables are always stored in Stack memory, while Reference Type variables are stored in Heap memory.

Example :
int num = 23; // 23 will assigned to num
Object Obj = num; // Boxing

Unboxing in C#
The process of converting a Reference Type variable into a Value Type variable is known as Unboxing.
It is an explicit conversion process.

Example :
int num = 23;         // value type is int and assigned value 23
Object Obj = num;    // Boxing
int i = (int)Obj;    // Unboxing
