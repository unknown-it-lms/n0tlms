Session 1 Git:
What is the primary purpose of a code versioning system?

A) To track changes to code over time
B) To compile code into executable programs
C) To optimize code performance
D) To document code architecture

Answer: A) To track changes to code over time

Explanation: Code versioning systems are primarily used to track changes made to code over time, facilitating collaboration among developers, and providing a history of modifications to the codebase.

Which of the following is not a commonly used code versioning system?

A) Git
B) Subversion (SVN)
C) Mercurial
D) Visual Studio

Answer: D) Visual Studio

Explanation: Visual Studio is an integrated development environment (IDE), not a code versioning system. Git, Subversion (SVN), and Mercurial are examples of commonly used version control systems.

In a code versioning system, what is a "commit"?

A) A request to merge code changes
B) A record of changes made to the codebase
C) A notification of code errors
D) A unit of code compilation

Answer: B) A record of changes made to the codebase

Explanation: A commit is a record of changes made to the codebase. It typically includes a description of the changes and the files affected.

What is branching in a code versioning system?

A) Merging multiple codebases into one
B) Creating a parallel line of development
C) Assigning version numbers to code releases
D) Reviewing code changes before committing

Answer: B) Creating a parallel line of development

Explanation: Branching allows developers to create separate lines of development, enabling them to work on features or fixes independently without affecting the main codebase.

Which command is used to retrieve the latest changes from the remote repository in Git?

A) git push
B) git pull
C) git commit
D) git fetch

Answer: B) git pull

Explanation: git pull is used to retrieve the latest changes from the remote repository and merge them into the local branch.

What is a "conflict" in the context of code versioning?

A) A disagreement among developers
B) An error in the code syntax
C) A situation where changes cannot be automatically merged
D) A discrepancy between code comments and functionality

Answer: C) A situation where changes cannot be automatically merged

Explanation: A conflict occurs when the changes made by one developer cannot be automatically merged with the changes made by another developer, requiring manual resolution.

Which code versioning system uses a centralized repository model?

A) Git
B) Mercurial
C) Subversion (SVN)
D) Bitbucket

Answer: C) Subversion (SVN)

Explanation: Subversion (SVN) uses a centralized repository model where all versioned files are stored in a central server, and users check out copies of files from this central location.

What is the purpose of a "merge" operation in a code versioning system?

A) To revert changes made to the codebase
B) To combine changes from different branches
C) To create a new branch
D) To synchronize local and remote repositories

Answer: B) To combine changes from different branches

Explanation: The merge operation combines changes from different branches into a single branch, integrating the modifications made by different developers.

Which of the following is an example of a distributed code versioning system?

A) Git
B) Perforce
C) ClearCase
D) TFS (Team Foundation Server)

Answer: A) Git

Explanation: Git is a distributed version control system where each developer has a complete copy of the repository, allowing for more flexibility and decentralized collaboration.

What is the purpose of version control in software development?

A) To ensure that all code is error-free
B) To manage changes to the codebase over time
C) To automatically generate documentation
D) To optimize code execution speed

Answer: B) To manage changes to the codebase over time

Explanation: Version control systems are used to manage changes to the codebase over time, enabling collaboration among developers, tracking modifications, and facilitating code maintenance and troubleshooting.

History of version Control
When was the concept of version control first introduced?
a) 1960s
b) 1970s
c) 1980s
d) 1990s

Answer: b) 1970s

Explanation: The concept of version control first emerged in the 1970s with the development of early systems like SCCS (Source Code Control System) and RCS (Revision Control System).
Which of the following was one of the earliest version control systems?
a) Git
b) SVN (Subversion)
c) Mercurial
d) CVS (Concurrent Versions System)

Answer: d) CVS (Concurrent Versions System)

Explanation: CVS (Concurrent Versions System) was one of the earliest version control systems, released in the early 1990s.

Who developed the Concurrent Versions System (CVS)?
a) Linus Torvalds
b) Guido van Rossum
c) Brian Behlendorf
d) Dick Grune

Answer: c) Brian Behlendorf

Explanation: CVS was initially developed by Brian Behlendorf.

What year was CVS first released?
a) 1990
b) 1995
c) 2000
d) 2005

Answer: b) 1995

Explanation: CVS was first released in 1995.
Git, a widely used distributed version control system, was created by:
a) Linus Torvalds
b) Guido van Rossum
c) Larry Wall
d) James Gosling

Answer: a) Linus Torvalds

Explanation: Git, the distributed version control system, was created by Linus Torvalds, the creator of the Linux kernel.
Which of the following is not a distributed version control system?
a) Git
b) Mercurial
c) SVN (Subversion)
d) Bazaar

Answer: c) SVN (Subversion)

Explanation: SVN (Subversion) is a centralized version control system, unlike Git, Mercurial, and Bazaar which are distributed version control systems.
Mercurial, another distributed version control system, was initially developed by:
a) Google
b) Mozilla
c) Microsoft
d) Facebook

Answer: b) Mozilla

Explanation: Mercurial was initially developed by Matt Mackall, sponsored by Fog Creek Software, and later maintained by the Mozilla Foundation.
What year was the first release of Git?
a) 2000
b) 2002
c) 2005
d) 2007

Answer: c) 2005

Explanation: The first release of Git was in 2005.
Which version control system was developed as an alternative to CVS, aiming to address some of its limitations?
a) Git
b) SVN (Subversion)
c) Mercurial
d) Bazaar

Answer: d) Bazaar

Explanation: Bazaar was developed as an alternative to CVS, addressing some of its limitations.

The main advantage of distributed version control systems over centralized ones is:
a) Simplicity of use
b) Better performance on large projects
c) More flexibility and offline access
d) Tight integration with IDEs

Answer: c) More flexibility and offline access

Explanation: The main advantage of distributed version control systems over centralized ones is their ability to provide more flexibility and support for offline access, allowing developers to work independently and merge changes later.

3. What is the purpose of version control?

A) To track changes in source code

B) To manage project deadlines

C) To debug software

D) To optimize database queries

Answer: A) To track changes in source code

Explanation: Version control systems like Git help developers manage changes to source code over time, enabling collaboration and tracking revisions.

4. Which of the following is a centralized version control system?

A) Git

B) Mercurial

C) Subversion (SVN)

D) CVS (Concurrent Versions System)

Answer: C) Subversion (SVN)

Explanation: Subversion (SVN) is a centralized version control system where all files and history are stored on a central server.

5. What is a 'commit' in Git?

A) A software development framework

B) A type of branch

C) A snapshot of changes made to files

D) A version control command

Answer: C) A snapshot of changes made to files

Explanation: In Git, a commit captures the current state of the repository, including changes made to files, along with a commit message describing the changes.

6. What is the primary purpose of branching in version control systems like Git?

A) To merge unrelated projects

B) To isolate new development work from the main codebase

C) To delete unnecessary files

D) To create backups of the repository

Answer: B) To isolate new development work from the main codebase

Explanation: Branching allows developers to work on new features or bug fixes without affecting the main codebase until the changes are ready to be merged.

7. Which command is used to merge changes from one branch to another in Git?

A) git commit

B) git merge

C) git checkout

D) git pull

Answer: B) git merge

Explanation: The git merge command is used to integrate changes from one branch into another.

8. What is a 'conflict' in the context of version control systems?

A) A disagreement between team members

B) A merge error that occurs when changes conflict with each other

C) A security vulnerability

D) A bug in the version control software

Answer: B) A merge error that occurs when changes conflict with each other

Explanation: Conflicts arise when changes made in different branches cannot be automatically merged by the version control system, requiring manual intervention to resolve.

9. Which version control system was developed by Linus Torvalds?

A) Subversion (SVN)

B) Git

C) Mercurial

D) CVS (Concurrent Versions System)

Answer: B) Git

Explanation: Git was created by Linus Torvalds in 2005 to manage the Linux kernel development.

10. What is the purpose of a 'pull request' in Git-based workflows like GitHub?

A) To request permission to delete a branch

B) To request a review of changes before merging them into the main branch

C) To request access to a private repository

D) To request a rollback of changes to a previous version

Answer: B) To request a review of changes before merging them into the main branch

Explanation: A pull request is a feature in Git-based platforms like GitHub that allows developers to propose changes and request feedback and review from other team members before merging them into the main branch.

Software development workflow


1. What is the purpose of a software development workflow?

A) To write code quickly without any planning

B) To manage project budgets

C) To provide a structured approach to software development

D) To document software bugs

Answer: C) To provide a structured approach to software development

Explanation: A software development workflow defines the steps and processes involved in the creation of software, ensuring a structured and systematic approach to development.

2. Which of the following is NOT a common software development methodology?

A) Waterfall

B) Agile

C) Spiral

D) Circular

Answer: D) Circular

Explanation: Circular is not a commonly recognized software development methodology. The other options (Waterfall, Agile, Spiral) are well-known methodologies used in software development.

3. In Agile software development, what is the role of a Product Owner?

A) To write code

B) To manage the project schedule

C) To represent the stakeholders and prioritize tasks

D) To conduct software testing

Answer: C) To represent the stakeholders and prioritize tasks

Explanation: The Product Owner in Agile represents the stakeholders, defines product features, and prioritizes tasks in the development backlog.

4. What is a sprint in Agile methodology?

A) A meeting to discuss project progress

B) A period of time during which specific work is completed

C) A software testing phase

D) A documentation review process

Answer: B) A period of time during which specific work is completed

Explanation: In Agile, a sprint is a time-boxed period (usually 1-4 weeks) during which a set of work is completed and made ready for review.

5. Which software development methodology emphasizes continuous improvement and adaptation to change?

A) Waterfall

B) Agile

C) Spiral

D) Prototype

Answer: B) Agile

Explanation: Agile methodology emphasizes flexibility, adaptability, and continuous improvement through iterative development cycles.

6. What is the primary difference between Waterfall and Agile software development methodologies?

A) Waterfall focuses on iterative development, while Agile follows a linear approach.

B) Agile emphasizes adaptability and flexibility, while Waterfall follows a sequential process.

C) Waterfall involves continuous integration, while Agile relies on periodic releases.

D) Agile requires extensive documentation, while Waterfall emphasizes minimal documentation.

Answer: B) Agile emphasizes adaptability and flexibility, while Waterfall follows a sequential process.

Explanation: Waterfall follows a sequential process where each phase (requirements, design, implementation, testing, deployment) must be completed before moving to the next, while Agile is iterative and adaptable, allowing for changes and continuous improvement throughout the development process.

7. What is the purpose of Continuous Integration (CI) in software development?

A) To manually test the software before release

B) To integrate code changes into a shared repository frequently

C) To automate the deployment process

D) To review code quality and performance metrics

Answer: B) To integrate code changes into a shared repository frequently

Explanation: Continuous Integration (CI) involves automatically integrating code changes into a shared repository several times a day, ensuring that each integration does not break the build and enabling early detection of integration errors.

8. Which of the following is a key principle of DevOps?

A) Siloed teams

B) Manual deployment processes

C) Continuous collaboration and communication

D) Waterfall development methodology

Answer: C) Continuous collaboration and communication

Explanation: DevOps emphasizes collaboration and communication between development, operations, and other stakeholders to enable faster and more reliable software delivery.

Which command is used to initialize a new Git repository?
A) git init
B) git add
C) git commit
D) git clone

Answer: A) git init

Explanation: The git init command is used to initialize a new Git repository in the current directory.

What does the command git add do?
A) Adds changes to the working directory
B) Adds changes to the staging area
C) Commits changes to the repository
D) Deletes the repository

Answer: B) Adds changes to the staging area

Explanation: The git add command adds changes from the working directory to the staging area, preparing them to be committed.

What is the purpose of the command git commit?
A) Adds changes to the working directory
B) Adds changes to the staging area
C) Commits changes to the repository
D) Deletes the repository

Answer: C) Commits changes to the repository

Explanation: The git commit command records the changes staged in the staging area to the repository along with a commit message.

How can you view the commit history in Git?
A) git log
B) git status
C) git branch
D) git checkout

Answer: A) git log

Explanation: The git log command displays a list of commits in the repository, showing information such as commit hash, author, date, and commit message.

What does the command git push do?
A) Pushes changes to a remote repository
B) Pulls changes from a remote repository
C) Creates a new branch
D) Deletes a branch

Answer: A) Pushes changes to a remote repository

Explanation: The git push command is used to push the committed changes from the local repository to a remote repository.

How can you create a new branch in Git?
A) git new-branch
B) git branch create
C) git branch
D) git checkout -b

Answer: D) git checkout -b

Explanation: The git checkout -b command creates a new branch and switches to it in one step.
