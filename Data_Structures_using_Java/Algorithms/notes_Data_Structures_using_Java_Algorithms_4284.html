Complexity
Algorithmic complexity is a measure of how long an algorithm would take to complete given an input of size n. If an algorithm has to scale, it should compute the result within a finite and practical time bound even for large values of n. For this reason, complexity is calculated asymptotically as n approaches infinity. While complexity is usually in terms of time, sometimes complexity is also analyzed in terms of space, which translates to the algorithm's memory requirements.

Analysis of an algorithm's complexity is helpful when comparing algorithms or seeking improvements.
Asymptotic Notations
Following are the commonly used asymptotic notations to calculate the running time complexity of an algorithm.
  1. Ο Notation
  2. Ω Notation
  3. θ Notation

  • Big Oh Notation, Ο
The notation Ο(n) is the formal way to express the upper bound of an algorithm's running time. It measures the worst case time complexity or the longest amount of time an algorithm can possibly take to complete.
  • Omega Notation, Ω
The notation Ω(n) is the formal way to express the lower bound of an algorithm's running time. It measures the best case time complexity or the best amount of time an algorithm can possibly take to complete.
  • Theta Notation, θ
The notation θ(n) is the formal way to express both the lower bound and the upper bound of an algorithm's running time.
Real-world examples of various algorithmic complexities.
Suppose you're looking for a specific item in a long unsorted list, you'll probably compare with each item. Search time is proportional to the list size. Here complexity is said to be linear.

On the other hand, if you search for a word in a dictionary, the search will be faster because the words are in sorted order, you know the order and can quickly decide if you need to turn to earlier pages or later pages. This is an example of logarithmic complexity.

If you're asked to pick out the first word in a dictionary, this operation is of constant time complexity, regardless of number of words in the dictionary. Likewise, joining the end of a queue in a bank is of constant complexity regardless of how long the queue is.

Suppose you are given an unsorted list and asked to find all duplicates, then the complexity becomes quadratic. Checking for duplicates for one item is of linear complexity. If we do this for all items, complexity becomes quadratic. Similarly, if all people in a room are asked to shake hands with every other person, the complexity is quadratic.

Divide and Conquer Algorithm
The Divide and Conquer algorithm is a powerful and widely used problem-solving paradigm in computer science. It works by recursively breaking down a complex problem into smaller, more manageable sub-problems of the same type, until these sub-problems become simple enough to be solved directly. The solutions to these sub-problems are then combined to solve the original larger problem.
Key Steps
  1. Divide: Split the problem into smaller sub-problems. These should be similar to the original problem but easier to solve.
  2. Conquer: Solve the sub-problems recursively. If the sub-problems are small enough, solve them directly.
  3. Combine: Merge the solutions of the sub-problems to form the solution to the original problem.
Examples
  • Merge Sort: A classic sorting algorithm that divides an array into two halves, recursively sorts each half, and then merges the two sorted halves.
  • Quick Sort: Another popular sorting algorithm that partitions an array around a "pivot" element, recursively sorts the sub-arrays, and then the combined result is already sorted.
  • Binary Search: This algorithm efficiently searches for an element in a sorted array by repeatedly dividing the search interval in half.
Greedy algorithm
A greedy algorithm is a problem-solving technique that makes the best choice at each step, aiming for a locally optimal solution with the hope of finding a global optimum. It is called "greedy" because it makes decisions based on the best immediate benefits without considering the overall consequences.
Key Steps
  • Local Optimization: At every step, the algorithm chooses the option that appears to be the best or most beneficial at that moment, without considering the long-term consequences of that choice. It's "short-sighted."
  • No Backtracking: Once a decision is made, it's final. The algorithm doesn't go back and reconsider previous choices, even if they might lead to a better overall solution later.
  • ​​​​​​​Hope for Global Optimum: The core assumption (or hope) is that a sequence of locally optimal choices will ultimately lead to a globally optimal solution for the entire problem.
Examples
  • Scheduling: Assigning resources to tasks in a way that minimizes waiting time.
  • Routing: Finding the shortest path in navigation systems. For example, Dijkstra's algorithm
  • Huffman Coding: Used in data compression algorithms.
  • Minimum Spanning Tree (MST): Prim's and Kruskal's algorithms.
Dynamic Programming algorithm
Dynamic Programming is a method for solving optimization problems by breaking them down into simpler, overlapping subproblems where results of already solved sub-problems are stored and re-used to avoid redundant calculations. 
Unlike Divide and Conquer, which typically solves independent subproblems, Dynamic Programming addresses problems where the subproblems overlap. This means the same subproblem might be encountered multiple times during the computation. Dynamic Programming tackles this by solving each subproblem only once and storing its solution, so that it can be reused later. This avoids redundant computations and significantly improves efficiency.
Steps
  • This is a recursive approach that starts from the main problem and recursively breaks it down into subproblems.
  • Once the results of subproblems are computed, they are stored usually in an array or hash table (Generally called as "memo").
  • ​​​​​​​Before computing next subproblem, it first checks if the result is already in the memo. If it is, it simply returns the stored value. Otherwise, it computes the value, stores it, and then returns it.
Examples
  • Fibonacci Series: fib(n) = fib(n-1) + fib(n-2)
  • Longest Common sub-sequence (LCS): Finding the longest sub-sequence common to two sequences.
  • Coin Change Problem: Given an amount and denominations of coins, we can use dynamic programming to determine the minimum number of coins needed to make that amount.
Brute force algorithm
A Brute Force Algorithm is the most straightforward and fundamental approach to solving a problem. It works by trying every possible solution or combination until it finds one that satisfies the problem's conditions. Essentially, it's about exhaustively searching the entire solution space. This is very in-efficient algorithm.
Steps
  • Generate all possible solutions.
  • Test each solution: For each generated solution, check if it meets the criteria of the problem.
  • Return the valid solution
Examples
  • Linear Search: Searching for an element in an unsorted list by checking each element one by one from beginning to end.
  • ​​​​​​​Password Cracking: In cybersecurity, brute force methods are used to guess passwords by trying every possible combination until the correct one is found. Though effective, this method can take a long time if the password is complex.
  • Bubble Sort / Selection Sort
Backtracking algorithms
A Backtracking algorithm is a general algorithmic technique for solving problems that involve searching for a solution among a set of choices. It systematically builds a solution incrementally, one step at a time. If at any point it determines that the current partial solution cannot possibly lead to a valid or optimal complete solution, it "backtracks" (undoes the last choice) and tries a different option.
Steps
  • Define a Solution State
  • Make a Choice: From the current state, choose one of the available options to extend the partial solution.
  • Check for Validity/Constraints: After making a choice, check if the current partial solution is still valid according to the problem's constraints. If valid, recursively call the backtracking function to continue building the solution. If invalid (or leads to a dead end) do backtracking, means undo the last choice, and return to the previous state to try a different option.
  • If a complete valid solution is found, record it. If no more choices are available at the current level, backtrack to the previous level.
Examples
  • Solving a Sudoku Puzzle
  • Maze Solving: Finding a path from a start point to an end point in a maze.
  • Combination Sum / Subset Sum Problems: Finding combinations or subsets of numbers that sum up to a target value.
Branch-and-bound algorithms
Branch-and-bound algorithms are used to solve optimization problems, especially in situations where you need to find the best possible solution from a set of feasible solutions. It systematically explores and narrows down the search space to find the best solution among many possible solutions. It is a more refined version of exhaustive search (like brute force) that uses clever techniques to avoid exploring unproductive parts of the solution space.
Steps
  • Branching: This involves dividing the problem into smaller parts or branches. Each branch represents a subset of the possible solutions. 
  • Bounding: This is the process of calculating an upper or lower bound on the best solution that can be achieved from a given branch. If the bound indicates that this branch cannot yield a better solution than the current best, it can be discarded.
Examples
  • Traveling Salesman Problem (TSP): Consider a salesman who needs to visit several cities and return to the starting point, minimizing the total distance traveled.
  • Vehicle Routing Problems: Optimizing routes for a fleet of vehicles.
  • Facility Location Problems: Deciding where to locate facilities to minimize costs.
Stochastic algorithms
A Stochastic Algorithm is an algorithm that incorporates randomness as a part of its logic or procedure. Unlike deterministic algorithms, which will always produce the same output for the same input, a stochastic algorithm might produce different outputs (or take different paths to the same output) even with identical inputs, due to the element of chance.
Steps
  • Start with a Random Solution: 
  • Make Random Changes: Change your current solution slightly. Accept or Reject Changes
  • Over time, you decrease the probability of accepting worse solutions, guiding the search toward the best solution.
Examples
  • Randomized Quicksort ​​​
  • Monte Carlo Tree Search (MCTS)
  • PageRank Algorithm (Google Search)
