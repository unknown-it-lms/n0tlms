Spring MVC with database
​​​​​​​In this chapter we will learn about implemnting MVC with the help of database so that view generated can be using data from the persistent storage.
Spring MVC with JDBC
​​​​​​​Spring provides a simplification in handling database access with the Spring JDBC Template. The Spring JDBC Template has the following advantages compared with standard JDBC.
Simplified API:
It provides a higher-level API that helps programmer to avoid much of the boilerplate code required for database interactions.
Automatic resource management:
It handles resource management tasks like opening and closing connections, statements, and result sets automatically, reducing the risk of errors and improving code maintainability.
Error handling:
It provides built-in support for error handling, making it easier to handle exceptions and recover from database errors. It Automatically catches and translates JDBC exceptions into Spring-specific exceptions, making it easier to handle errors and write more robust code.
Template methods:
It offers template methods that can be customized to suit different use cases, providing flexibility and reusability. Simple methods that are available are query(), update(), queryForList(), queryForObject() etc
Integration with Spring ecosystem: It integrates seamlessly with other Spring components, such as Spring Data and Spring Security, making it easier to build complex database-driven applications.
Simplified transaction management:
Integrates with Spring's transaction management features, making it easy to manage transactions across multiple database operations.

JDBCTemplate
​​​​​​​It is the central class in the Spring JDBC support classes. It takes care of creation and release of resources such as creating and closing of connection object etc. So it will not lead to any problem if you forget to close the connection.
It handles the exception and provides the informative exception messages by the help of excepion classes defined in the org.springframework.dao package.
We can perform all the database operations by the help of JdbcTemplate class such as insertion, updation, deletion and retrieval of the data from the database. Following is the declaration for org.springframework.jdbc.core.JdbcTemplate class −
public class JdbcTemplate extends JdbcAccessor implements JdbcOperations
Usage
Step 1 − Create a JdbcTemplate object using a configured datasource.
Step 2 − Use JdbcTemplate object methods to make database operations.
Example :
Following example will demonstrate how to read a query using JdbcTemplate class. We'll read the available records in Student Table.
Syntax
String selectQuery = "select * from Student";
List <Student> students = jdbcTemplateObject.query(selectQuery, new StudentMapper());
The Spring JDBC template offers several ways to query the database. queryForList() returns a list of HashMaps. The name of the column is the key in the hashmap for the values in the table. More convenient is the usage of ResultSetExtractor or RowMapper which allows to translates the SQL result direct into an object (ResultSetExtractor) or a list of objects (RowMapper).
JdbcTemplate class provides many convenience methods for doing things such as converting database data into primitives or objects, executing prepared and callable statements, and providing custom database error handling.

Spring MVC with ORM
​​​​​​​Spring provides a simplification in handling database access with the spring ORM module. The Spring ORM has the advantages compared with standard JDBC.
Spring provides API to easily integrate Spring with ORM frameworks such as Hibernate, JPA(Java Persistence API), JDO(Java Data Objects), Oracle Toplink and iBATIS.
Advantage of ORM Frameworks with Spring
There are a lot of advantage of Spring framework in respect to ORM frameworks. There are as follows:
  1. Less coding is required: By the help of Spring framework, you don't need to write extra codes before and after the actual database logic such as getting the connection, starting transaction, commiting transaction, closing connection etc.
  2. No need to write queries. All operations are in terms of objects
  3. Easy to test: Spring's IoC approach makes it easy to test the application.
  4. Better exception handling: Spring framework provides its own API for exception handling with ORM framework.
  5. Integrated transaction management: By the help of Spring framework, we can wrap our mapping code with an explicit template wrapper class or AOP style method interceptor.
HibernateTemplate
​​​​​​​The Spring framework provides HibernateTemplate class, so you don't need to follow so many steps like create Configuration, BuildSessionFactory, Session, beginning and committing transaction etc. So it saves a lot of code. So it saves a lot of code.
1. Spring HibernateTemplate is a helper class that simplifies Hibernate data access code.
2. It automatically converts HibernateExceptions into DataAccessExceptions.
3. The central method of HibernateTemplate is execute that accepts HibernateCallback.
4. ​​​​​​​It offers a variety of methods for performing CRUD (Create, Read, Update, Delete) operations, executing queries, and managing transactions.
5. The execute method provides Hibernate session handling. It means neither the HibernateCallback implementation nor the calling code needs to explicitly care about retrieving/closing Hibernate Sessions, or handling Session lifecycle exceptions.
6. The HibernateTemplate is instantiated using SessionFactory either in @Configuration class or in XML configuration

5. Managing transactions
@Transactional
public void doSomething() {
    // do some work
}
This is much more readable, more maintainable, less cumbersome, and safer since Spring handles the transactional logic for you. That's why a transaction manager is needed to tell Spring how it should handle the transactions for you by declaring bean for HibernateTransactionManager.
    <bean id="txManager" class="org.springframework.orm.hibernate5.HibernateTransactionManager" >
        <property name="sessionFactory" ref="sf"/>
    </bean>
 Above bean works in co-ordination with @Transactional annotation added in the service layer either above the class or above the method. For this we have to declare either following element in bean definition file or use @EnableTransactionManagement annotation in the configuration class.  
<tx:annotation-driven transaction-manager="txManager"/>
