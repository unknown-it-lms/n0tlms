In this topic, we will be focusing scriptless JSP elements like std actions, EL etc and will be understanding in depth about MVC architecture and its implementation in web application.
Std Actions
JSP standard actions, also referred to as JSP tags, are special elements which can be embedded within the JSP page to achieve various functionalities. These tags use XML like syntax and are processed by the JSP container during page translation. Std actions are the tags starting with jsp prefix. 
Examples of std actions 
Flow Control: Some actions like jsp:forward and jsp:include help in managing navigation between JSP pages. jsp:forward redirects the request to a different resource, while jsp:include embeds content from another JSP file into the current page.
Std actionUsage
<jsp:forward page="/home.jsp" />Equivalent with forward method of RequestDispatcher
<jsp:include page="/home.jsp" />Equivalent with include method of RequestDispatcher

Java Bean Manipulation: Actions like jsp:useBean, jsp:setProperty, and jsp:getProperty can be used to create or locate beans, set their properties, and access their property values.
Std actionUsage
<jsp:useBean id="product" class="com.example.Product" scope="session" />Create or locate the bean
<jsp:setProperty name="product" property="name" param="productName" />Set bean properties using request parameters
<p>Product Name: <jsp:getProperty name="product" property="name" /></p>Access and display bean properties

Dynamic Content Generation: Tags like jsp:body, jsp:attribute, and jsp:text enable you to dynamically define content based on various factors. jsp:body helps define a dynamic body for XML elements, while jsp:attribute and jsp:text are used for setting and printing attributes and text content respectively.

Other Actions: Additional tags like jsp:plugin and jsp:param cater to specific purposes. jsp:plugin helps generate HTML for Java plugins, and jsp:param is used with jsp:forward and jsp:include to pass parameters between pages.
Overall, JSP standard actions provides a way to get rid of java code from JSP separating presentation logic (JSP) from business logic (Java Beans).

Bean Related Std Actions
JSP provides mechanisms to interact with beans created and access and update it's properties. Some std actions are specifically available for creating and accessing the beans at different scopes(typically created by servlets).
Java beans
Java Beans are java objects that have properties, which can be read via a get method or changed via a set method. A java bean should not have any public variables. All the variables should be accessed using the getter/setter methods.
  • It should have default constructor compulsorily
  • It can have any number of parameterised constructors
  • It should have getter and setter having a particular format e.g. if fname(String) is the name of the property then
  • it's getter method would be String getFname()
  • and setter method would be void setFname(String fname)
  • It can have any additional business logic methods

MVC Architecture
​​​​​​​MVC (Model-View-Controller) is a widely used architectural design pattern for developing web applications. It separates the application into three separate components: model, view and controller
Model
  • Represents the business data and core business logic of your application.
  • Typically implemented as Java classes (entities) that encapsulate data and related operations.
  • Can interact with databases or other data sources to manage and persist data.
View
  • Represents the visual layer of your application, responsible for presenting information to the user.
  • In web applications, views are often implemented using HTML, CSS, and JavaScript.
  • Views can display data retrieved from the model and potentially accept user input.
Controller
  • Acts as an intermediary between the view and the model.
  • Handles incoming user requests (e.g., button clicks, form submissions).
  • Communicates with the model to fetch or update data as needed.
  • Prepares data for the view and selects the appropriate view template to display.
Benefits of MVC:
  • Separation of Concerns: Isolates concerns like data management, business logic, and presentation into distinct components. This improves code maintainability, reusability, and testability.
  • Flexibility: Changes to one component (e.g., the view) often don't require modifications in other components (e.g., the model).
  • Testability: Each layer (model, view, controller) can be tested independently, making development and debugging easier.
Steps for MVC implementation
  1. Request is accepted in servlet which acts as a controller.
  2. Servlet processes the request, can communicate with database layer and perform either retrieve or update operation from the database.
  3. Data that should be sent back in the response will be kept in the form of attributes at required scopes(request, session or application). Theses attributes can be single object, collection of objects which acts as a model(Java bean)
  4. Forward the request to appropriate JSP(view)
  5. Views can access data from attributes at a particular scope.
  6. Views can use preferable std actions, EL or JSTL for displaying the data
