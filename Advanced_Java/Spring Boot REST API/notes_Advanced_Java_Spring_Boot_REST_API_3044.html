Spring Boot REST API
​​​​​​​In this chapter we will learn about developing REST API using basic knowledge of Spring boot. Developing REST API is very easy and quick so helps in rapid application development
REST API basics
  • REST stands for REpresentational State Transfer, a standardized approach to building web services.
  • A REST API is a service that transfers requests and responses between two software systems, on a REST architecture.
  • A REST API is an intermediary Application Programming Interface that enables two applications to communicate with each other over HTTP, much like how servers communicate to browsers.
  • RESTful is the most common approach for building web services because of they are easy to learn and build.
  • REST is mainly producing and consuming JSON data
  • The REST architecture builds web services that are accessible through URLs using mainly one of four request verbs: POST, GET, PUT, and DELETE. So, you could say a REST API is software that allows you to create, read, update, and delete resources via URLs.
  • Let's say you order something from a fast-food restaurant and the cashier requests the information needed from you to process your order. After it's been processed, they hand you the order you requested for. This transaction is a real-life example of how REST API works.

Setting application database
Next, before we start working on the application, we'll want to set up the database. This can easily be done through Spring Data JPA, which allows us to set this connection up with just a couple of parameters.
It abstracts away everything needed to be done by the developer, and allows us to switch underlying databases if we'd like, just by changing a couple of properties.
To tell Spring how to connect to your preferred database, in your application.properties file
spring.datasource.url = jdbc:mysql://localhost:3306/user
spring.datasource.username = user
spring.datasource.password = user
spring.jpa.hibernate.ddl-auto = update
spring.jpa.properties.hibernate.dialect = org.hibernate.dialect.MySQL5Dialect
datasource.url, username and password are required for database connectivity. The jpa.hibernate.ddl-auto property directly influences the hibernate.hbm2ddl.auto property, and essentially defines how Hibernate should handle schema tool. management.
Developing different layers
Spring Boot REST APIs typically follow a layered architecture for better organization, maintainability, and testability. We will understand tasks, requirements and importance of each layer
Presentation layer
  • This is the outermost layer which communicates with the client which is generally a web browser of any client side application component like react component.
  • This is a class annotated with @RestController annotation and contains methods which are mapped with specific request URLs and  request methods.
  • This layer converts JSON data into objects and vice-versa
  • This layer is responsible for performing authentication and sending authenication details to business layer.
  • In short, the presentation layer is the equivalent of the Controller class. The Controller class handles all the incoming REST API requests (GET, POST, PUT, DELETE, PATCH) from the Client.
ContactController.java
import java.util.List;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;
import com.example.demo.entities.Contact;
import com.example.demo.services.ContactService;
@RestController
public class ContactController {
    @Autowired
    ContactService cservice;    
    @GetMapping("/getall")
    public List<Contact> getAll() {
        return cservice.getall();
    }    
    //will ne utilized for request URL http://localhost:8080/getcontact?cid=1
    @GetMapping("/getcontact")
    public Contact getOne(@RequestParam("cid")int cid) {
        return cservice.getOne(cid);
    }
    @PostMapping("/savecontact")
    public Contact save(@RequestBody Contact ct) {
        return cservice.save(ct);
    }    
}
Business layer
  • This layer is responsible for handling the core business logic of the application.
  • It interacts with the presentation layer (controllers) on one side and the persistence layer (repositories) on the other side.
  • Services typically don't handle HTTP requests directly but are called by controllers.
  • This layers can handle some tasks like clubbing the data returned from multiple repositories to send meaningful response to the client, performing computations on the data received from repository, calling some external service, managing transactions.

import java.util.List;

    @Autowired

    }

         Contact ct=null;

         try {
             ct = opt_ct.get();
         }
         catch(Exception e)  {
             ct=null;
         }

    }

        return crepo.save(ct);
    }    
}
Persistence layer
  • This layer handles data persistence and retrieval and update operations from a data source like a database.
  • It uses repositories which are interfaces extending CrudRepository or JpaRepository to interact with the database
  • Repositories provide multiple methods for basic CRUD (Create, Read, Update, Delete) operations on the entities. Custom methods can be written in the repository based on any specific requirement.
  • Implementations of these repository interfaces are provided by spring framework automatically.
  • This helps in reducing boilerplate code and focusing on what data is needed rather than constructing a query.

Custom operations
In repository interface, we can create custom methods for retrieving specific data and for updating some records in database. These custom methods will help in extending the functionality of JPA repository beyond CRUD operations.
JPQL (Java Persistence Query Language)
JPQL works with the application's entities and properties rather than tables and columns. JPA translates JPQL queries into appropriate SQL statements based type of database.
A typical JPQL will have following format:
SELECT [selection] FROM [entity name] [WHERE clause] [ORDER BY clause]
Note:
  • WHERE and ORDER BY clauses are optional
  • Select can select the entire entity or only few properties or some agreegate function with property
  • from indicates the entity class mapped with database table
  • JPQL can use subqueries, join operations where based on entity mappings.
  • JPQL can use parameters which with placeholers (using either names or sequence)

Defining custom methods
Define custom methods annotated with @Query annotation including query as a string written in JPQL for all the custom operations. Example :
@Query("select c from Contact c where fname like :str")
public List<Contact> getcontacts(String str);

Method naming conventions
we can create query methods to select records from the database without writing SQL queries. Spring Data JPA will create SQL queries based on the query method and execute the query. We can create query methods for the repository using Entity fields referred as finder methods (findBy, findAll etc..)
Following are the examples of keywords:
1. And - findByLastnameAndFirstname - where x.lastname = ?1 and x.firstname = ?2
2. Is, Equals - findByFirstname, findByFirstnameIs, findByFirstnameEquals -  where x.firstname = ?1"
3. Between - findByStartDateBetween - where x.startDate between ?1 and ?2
4. GreaterThanEqual - findByAgeGreaterThanEqual - where x.age >= ?1
5. EndingWith - findByFirstnameEndingWith - where x.firstname like %?1
6. NotIn - findByAgeNotIn(Collection<Age> ages) - where x.age not in ?1
Native SQL queries
For some situations we can use native SQL queries. Annotate your method with @Query and specify the native SQL query along with the nativeQuery attribute set to true.
@Query(value = "select * from contacts where fnanme like :str",nativeQuery = true)
public List<Contact> getcontacts1(String str);
Native queries are preferred when we want to write database specific queries or in some cases where multiple levels of entity relationships are used to optimize performance.
JPQL for update operation
Spring Data JPA provides the @Modifying annotation that allows you to define update queries directly within your repository interface using JPQL. 
@Modifying
@Query("update Contact set email = ?2 where cid =?1")
public int updateEmail(int cid,String email);
The query itself follows the standard JPQL update syntax with UPDATE followed by the entity name, a set clause to specify changes, and a where clause for filtering.
The method returns the number of entities updated (useful for bulk updates).
Executing procedures
Using @NamedStoredProcedureQuery and @Procedure annotation, we can define the stored procedure and its parameters within your repository interface methods.
@NamedStoredProcedureQuery(name = "update_user_email", procedureName = "update_user_email_proc")
@Procedure(procedureName = "update_user_email_proc", parameters = {
      @StoredProcedureParameter(mode = ParameterMode.IN, name = "user_id", type = Long.class),
      @StoredProcedureParameter(mode = ParameterMode.IN, name = "new_email", type = String.class)
  })
void updateEmailById(Long userId, String newEmail);
Handling Date columns
Spring Data JPA supports mapping classes like java.util.Date, java.sql.Date, LocalDate (Java 8 and above) and LocalDateTime (Java 8 and above) to your database date columns.
@Temporal annotation can be used on the entity class properties to specify how the date is mapped to the database column. 
@Temporal(TemporalType.DATE) is used for java.sql.Date or LocalDate columns storing dates only.
@Temporal(TemporalType.TIMESTAMP) is used for java.util.Date or LocalDateTime columns storing dates with time information
example:
@Column
@Temporal(TemporalType.DATE)
Date bdate;
Testing with postman
Postman is a versatile tool for testing APIs, and it's particularly well-suited for testing Spring Boot applications.
It provides a user-friendly interface for creating and sending HTTP requests, inspecting responses, and managing API collections.
Key features of Postman
  • Request Builder: Easily create and send various types of HTTP requests (GET, POST, PUT, DELETE, etc.).
  • Response Viewer: Inspect and analyze response data, including headers, body, and status codes.
  • Collections: Organize related requests into collections for better management and reusability.
  • Environments: Store and manage variables to parameterize requests and make them more dynamic.
  • Mock Servers: Simulate API behavior without a running backend for testing and development.
  • Scripting: Use JavaScript to automate tasks, validate responses, and perform complex operations.
  • API Documentation: Generate API documentation in various formats (e.g., OpenAPI, Postman Collections).
We will be predominently using the features of request builders, response viewers and helps testing organized into collections
Setting Up Postman for Spring Boot Testing
  1. Install Postman: Download and install Postman from https://www.postman.com/downloads/.
  2. Create a New Collection: This will group related requests. Name it something like "Spring Boot API Tests."
  3. Create a New Request: Within the collection, create a new request. Give it a descriptive name (e.g., "Get All Users").
Although creating collection is not compulsory, it is recommended to use for better organization
Configuring the Request
For testing a particular URL, minimum information that needs to be configured is request method and request URL.
  1. Method: Select the appropriate HTTP method (GET, POST, PUT, DELETE, etc.) based on your API endpoint.
  2. URL: Enter the base URL of your Spring Boot application, followed by the endpoint path. For example, if your application is running on http://localhost:8080 and you want to test the /users endpoint, the URL would be http://localhost:8080/users.
  3. Headers: Add any necessary headers, such as:
  4. Content-Type: Specify the content type of your request body (e.g., application/json).
  5. Authorization: If your API requires authentication, add the appropriate authorization header (e.g., Bearer <token>).
  6. Body: If your API requires a request body, add it here in the appropriate format (e.g., JSON, form data).
 Sending the Request
Click "Send": This will execute the request and display the response.
Inspecting the Response
Response can be verfied in the reponse view for
  • Status Code: Verify that the status code is as expected (e.g., 200 for successful requests, 400 for bad requests).
  • Headers: Check the response headers for any relevant information.
  • Body: Inspect the response body to ensure it contains the correct data.
