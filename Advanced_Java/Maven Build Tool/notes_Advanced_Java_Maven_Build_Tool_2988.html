Maven Build Tool
​​​​​​​Maven is an open-source project management and build automation tool. It primarily targets Java-based projects, but it can be used for others as well.
What is Buid Tool
​​​​​​​A build tool is a software program that automates the process of transforming source code into a usable or executable program. It essentially takes care of the behind-the-scenes tasks involved in getting your code ready to run. 
Basic tasks 
  1. Compiling: This translates human-readable code into a form the computer can understand (machine code or bytecode).
  2. Linking: Combines different pieces of compiled code and libraries into a single executable file.
  3. Packaging: Bundles all the necessary files (code, libraries, resources) into a single unit for easy distribution or deployment.
  4. Running Tests: Executes automated tests to identify any bugs or errors in the code
  5. Documentation : Generating documentation from the source code.
  6. Dependency Management: Keeps track of and downloads external libraries your project relies on.
  7. Installing: Installing the packaged code on a server, in a repository or somewhere else.
Benefits of using build tools:
  • Increased Efficiency: Automates repetitive tasks, saving developers time and effort.
  • Improved Consistency: Ensures everyone builds the project the same way, reducing errors.
  • Better Collaboration: Makes it easier for developers to work together on projects.
  • Streamlined Development Process: Provides a clear structure for building and testing code.

Build tools are essential in modern software development, especially for larger projects. There are many different build tools available, each with its own features. Some popular examples include Maven (for Java), Gradle (multi-language), Make (general-purpose), and Webpack (for web development).
Maven Installation
Prerequisites
Java Development Kit (JDK): Maven requires Java to be installed and configured on your system. You can download and install the latest JDK
Installation Steps for Windows
  1. Download the binary archive: Use the official Apache Maven website downloads section. Choose the appropriate binary distribution: Download the .zip archive for your operating system (e.g., apache-maven-3.9.8-bin.zip).
  2. Extract the archive: Extract the downloaded .zip file to a directory of your choice. We'll refer to this directory as <MAVEN_HOME> throughout the rest of the steps. A common location is C:\apache-maven-3.9.8.
  3. Set environment variables: You need to configure two environment variables
    MAVEN_HOME: Set this variable to point to the directory where you extracted the Maven archive (e.g., C:\apache-maven-3.9.8).
    PATH: Add the bin directory within your <MAVEN_HOME> directory to your system's PATH environment variable. This allows you to run Maven commands from any location in your command prompt.
  4. Verifying the Installation: Once you've completed the installation steps, open a new command prompt or terminal window and type mvn -v. If Maven is installed and configured correctly, you should see output showing the version of maven installed.
Eclipse with maven support
Eclipse offers built-in support for Maven through the M2Eclipse plugin. This integration allows you to seamlessly manage Maven projects within your Eclipse IDE.
Key Features:
  • Importing Existing Maven Projects: Import existing Maven projects from your local file system directly into your Eclipse workspace.
  • Creating New Maven Projects: Utilize the "New" -> "Other" -> "Maven" -> "Maven Project" wizard to create new projects with a pre-configured Maven structure.
  • Managing pom.xml: M2Eclipse provides dedicated editors for the pom.xml file, enabling you to view, edit, and manage project dependencies efficiently.
  • Running Maven Builds: Directly execute Maven goals (like clean, install, package) from within Eclipse. Right-click on your project or pom.xml and choose "Run As" -> "Maven build" to initiate the desired build process.
  • Viewing Console Output: The Eclipse console will display the output of Maven commands you execute within the IDE, providing insights into the build process.
  • Dependency Management: Browse and manage project dependencies directly within the IDE. M2Eclipse simplifies the process of adding, removing, or updating dependencies from your pom.xml.


Maven Overview
Following are the key concepts that we need to understand in maven
  1. Project Object Model (POM)
  2. Maven Repositories
  3. Build Lifecycle
  4. Profiles
  5. Dependency Management
Project Object Model (POM)
The heart of a Maven project is the pom.xml file, also known as the Project Object Model. This XML based file defines various aspects of your project, including:
  • Project information (name, group ID, artifact ID, version)
  • Dependencies on other libraries or projects
  • Build configurations (plugins, goals, profiles)
  • Repositories for downloading dependencies
Maven Repositories
Maven retrieves dependencies from repositories that store JAR (Java Archive) files and other artifacts. The default repository is Maven Central, a public repository hosting a vast collection of libraries. You can also configure private or custom repositories for project-specific dependencies.
Build Lifecycle
The build process in Maven is split up into build life cycles, phases and goals. A build life cycle consists of a sequence of build phases, and each build phase consists of a sequence of goals. If a life cycle is executed, all build phases in that life cycle are executed. If a build phase is executed, all build phases before it in the pre-defined sequence of build phases are executed.
Some common phases include:
  • clean: Deletes any build output from previous builds.
  • validate: Validates project configuration and dependencies.
  • compile: Compiles your source code into class files.
  • test: Executes unit tests associated with your project.
  • package: Packages the compiled classes and resources into a distributable archive (JAR file or WAR file).
  • verify: Verifies the build output (optional).
  • install: Installs the packaged artifact into your local Maven repository.
  • deploy: Deploys the artifact to a remote repository (optional).
Maven has 3 built-in build life cycles. These are:
  1. default - handles everything related to compiling and packaging
  2. clean - andles everything related to removing temporary files from the output directory, including generated source files, compiled classes, previous JAR files etc.
  3. site - handles everything related to generating documentation, it can generate a complete website with documentation
Plugins
Build plugins are used to insert extra goals into a build phase. If you need to perform a set of actions for your project which are not covered by the standard Maven build phases and goals. e.g Code analysis, CI server integration etc.
Profiles
Build profiles are used if you need to build your project in different ways. Profiles allow you to configure different build settings for various environments (development, testing, production).
You can activate specific profiles within the pom.xml or using command-line arguments.
Dependency Management
Maven manages project dependencies efficiently.
You declare dependencies in your pom.xml file, specifying the library name, group ID, artifact ID, and version.
Maven automatically downloads the required libraries and their transitive dependencies from repositories.
This ensures consistent versions across projects and simplifies development.

Maven Directory Structure
Maven has a standard directory structure. If that directory structure is followed for your project, you do not need to specify the directories of your source code, test code etc. in your POM file.
​
Name of the directoryDescription
myprojectdir Main root directory of the maven project. pom.xml file should reside in this directory
srcThe src directory is the root directory of your source code and test code.
mainThe main directory is the root directory for source code related to the application itself (not test code).
testThe test directory contains the test source code.
javaThe java directories under main and test contains the Java code for the application itself (under main) and the Java code for the tests (under test).
resourcesThe resources directory contains other resources like property files used for internationalization or configuration files.
webappThe webapp directory will be present in main, if your project is a web application. The webapp directory will then be the root directory of the web application. Thus the webapp directory contains the WEB-INF directory etc.
targetThe target directory is created by Maven. It contains all the compiled classes, JAR files etc. produced by Maven. When executing the clean build phase, it is the target directory which is cleaned.
